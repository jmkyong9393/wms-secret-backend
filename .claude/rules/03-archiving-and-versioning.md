# 아카이빙 · 시맨틱 버저닝 · 백업 규칙

## 문서 아카이빙 (수정 전 백업)

- 핵심 문서(기획서, 워크플로우, 아키텍처 명세서 등)를 최신화(버전업)하기 **전에**,
  반드시 해당 폴더 하위 `archive/` 폴더에 원본 파일을 버전명으로 백업한다.
  예: `요구사항정의서_ver1.4.0.2.md`
- `archive/` 폴더 내 파일은 **어떤 경우에도 내용 수정 금지** (Strict Read-only).
  이후 참조가 필요하면 새 버전을 만들고 다시 archive에 백업하는 방식으로만 갱신한다.
- 문서 전체를 스캔해 최신화가 덜 된 맥락(outdated content)을 선제적으로 찾아
  일괄 최신화한다 — 요청받은 부분만 좁게 고치지 않는다.

## 시맨틱 버저닝 (MAJOR.MINOR.PATCH.REVISION)

4단계 버전 구조를 엄격히 따른다 (예: `1.4.0.1`).

| 자리 | 변경 조건 |
|---|---|
| MAJOR (1.x.x.x → 2.x.x.x) | 프로젝트의 근본 목표나 전체 아키텍처가 완전히 뒤바뀔 때 |
| MINOR (1.4.x.x → 1.5.x.x) | 큰 틀의 기능 추가, 문서 핵심 섹션이 대폭 변경될 때 |
| PATCH (1.4.0.x → 1.4.1.x) | 기존 아키텍처 내 로직 보완, 자잘한 기능/흐름 추가·수정 |
| REVISION (1.4.0.0 → 1.4.0.1) | 오탈자 수정, 문장 다듬기, 포맷팅 등 사소한 변경 |

- 기획/기능 변경이나 리팩토링 단계 종료 시, 위 표를 기준으로 상향 단계를 먼저 판단해
  사용자에게 제안하고 승인받는다 (임의로 버전을 올리지 않는다).

## 일일 백업 절차

- 매일 오전 9시 이후 새 작업을 시작할 때, 가장 먼저 전날 작업 파일을 `archive/` 폴더
  아래 날짜별 폴더(예: `2026-07-07_폴더명`)로 정리한다.
- **원칙: 이동(Move) 금지, 반드시 복사(Copy)한다.** 루트 폴더에는 원본이 그대로 남아 있어야 한다.

## 인코딩 무결성

- 대량 문서 수정이나 스크립트를 통한 파일 일괄 변환 시, 덮어쓰기 전 원본 파일의 인코딩
  (UTF-8, CP949 등)을 먼저 확인(sniff)한다.
- 변환/저장 시 원본과 동일한 인코딩을 강제 유지하여 인코딩 파괴를 방지한다.
