# 폴더 구조 · 보안 등급 · 투트랙(Two-Track) 격리 규칙

## 레포지토리 역할 구분

- `wms-core-backend`, `wms-core-frontend` (개발 레포지토리, 배포/공개용)
  - 배포용 워크플로우, 공개 가능한 수준의 개발 계획서만 작성한다.
- `PM_정답지_백업` (PM 기밀 레포지토리, 비공개/세부 설계용)
  - 프로젝트 세부 사항, 대외 비공개 핵심 방어 논리, 세부 인프라 아키텍처(Blueprint)를 작성한다.
  - `PM_정답지_백업/SCI_논문_데이터수집_마스터플랜.md` — SCI급 논문 주제, 수집 데이터,
    실험 설계를 꾸준히 트래킹/업데이트한다.
- 그 외 주요 문서는 `WMS_docs`, `팀원개발가이드`, `과제정의서&워크시트` 내에서만 관리한다.
- **사용 금지 폴더**: `비동기큐버전` 등 과거 사용하던 폴더는 참조·수정하지 않는다.

## 보안 등급 (Confidentiality)

- `E:\취업\KT AIVLE School\빅프로젝트\PM_정답지_백업` — 최고 보안 구역
  (내부용, 대외비, 핵심 알고리즘 포함). 파일 훼손·유출 방지에 극도로 주의한다.
- `E:\취업\KT AIVLE School\빅프로젝트\WMS_docs` — 배포용 문서 전용 폴더.
  일반 배포 문서는 최대한 이곳에 배치한다.
- 배포용 문서를 갱신할 때는 이를 뒷받침하는 내부 상세 로직/대외비/핵심 알고리즘 문서를
  반드시 동시에 `PM_정답지_백업`에도 동기화한다 (대외 배포용 ↔ 내부 기밀용 이원화 유지).

## 팀원 개발 가이드 이원화 작성

- **마스터 가이드**: `팀원개발가이드` 루트 폴더. 기술 설명 + 완벽한 예시/정답 코드를 모두 기록
  (PM 리뷰/관리용).
- **배포용 가이드**: `팀원개발가이드\배포용` 폴더. **예시 코드나 정답 코드를 절대 포함하지 않는다.**
  개발 방향성, 아키텍처 목적, How-to-proceed(접근 방법)만 제공하여 팀원이 스스로 코드를
  작성하도록 유도한다.

## 투트랙(Two-Track) 완전 분리 원칙 (CRITICAL)

작업을 시작하기 전, 요청이 아래 두 트랙 중 어디에 속하는지 먼저 식별한다.
같은 주제라도 두 트랙의 세부 기획/진행 방향이 다를 수 있으므로 **컨텍스트 혼합을
원천 차단**한다.

| 구분             | 개인(PM/개별) 트랙                                                                    | 팀원(Team) 트랙                                                                   |
| ---------------- | ------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| 개발 폴더        | `develop\solo_develop\wms-secret-backend`, `develop\solo_develop\wms-secret-frontend` | `develop\team_develop\wms-core-backend`, `develop\team_develop\wms-core-frontend` |
| 문서 동기화 타겟 | `PM_정답지_백업`, `WMS_docs`                                                          | `팀원개발가이드`                                                                  |
| 절대 금지 구역   | `팀원개발가이드` 폴더 접근/수정 금지                                                  | `PM_정답지_백업`, `WMS_docs` 폴더 접근/수정 금지                                  |

- 트랙이 불명확한 요청을 받으면, 코드/문서를 건드리기 전에 사용자에게 트랙을 먼저 확인한다.
- 한 작업 세션 내에서 두 트랙의 폴더를 동시에 열람/수정하지 않는다.
