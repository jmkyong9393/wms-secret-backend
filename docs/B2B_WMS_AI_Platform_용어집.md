# 📖 비전공자를 위한 기술 용어 해설서 (Technical Glossary)

본 문서는 프로젝트 기획서 및 아키텍처 다이어그램에 등장하는 전문 기술 용어들에 대하여, **IT/개발 직군의 표준적인 기술 정의**를 명확히 서술함과 동시에 비전공자나 비즈니스 관계자도 직관적으로 이해할 수 있는 **쉬운 비유**를 곁들인 용어집입니다.

*(※ 대화 중 새롭게 등장하는 어려운 용어들은 이 문서에 지속적으로 자동 업데이트됩니다.)*

---

## 🏗️ 1. 물류 및 비즈니스 핵심 용어 (Business & WMS)

### B2B (Business to Business) vs B2C (Business to Consumer)
* **정의:** 거래의 대상이 '기업(출판사, 중고서점)'인지 '일반 개인 소비자'인지를 구분하는 비즈니스 모델 용어입니다. 우리 플랫폼은 출판사/물류센터 대상의 B2B 솔루션이면서, 동시에 개인의 중고책을 매입하는 C2B(Consumer to Business) 기능도 포괄합니다.
* **비유:** 대형 마트(B2B)에 물건을 납품하는 도매상과, 동네 슈퍼(B2C)에서 껌을 사는 손님의 차이입니다.

### WMS (Warehouse Management System)
* **정의:** 물류 창고 내의 입고, 보관(로케이션), 재고, 출고, 반품 등 모든 과정을 전산으로 관리하는 '창고 관리 시스템'입니다.
* **비유:** 도서관의 사서와 같습니다. 책이 들어오면 어디에 꽂을지 정해주고, 누가 빌려가면 기록을 남겨 빈자리를 파악합니다.

### UBCI (Used Book Condition Index - 자체 개발 상태 평가지수)
* **정의:** 단순히 "좋음/나쁨"이 아니라, 알라딘 매입 기준 등을 참고하여 훼손 부위(찢김, 오염, 낙서 등)를 정량적으로 계산해 산출하는 우리 플랫폼만의 독자적인 중고 도서 상태 점수입니다.
* **비유:** 소고기의 마블링 등급 판정표와 같습니다. 주관적인 느낌이 아니라 명확한 채점표에 의해 등급(MINT~SCRAP)이 매겨집니다.

### Dynamic Pricing (동적 가격 책정)
* **정의:** 출고 시 똑같은 등급(예: B급)이더라도, UBCI 세부 점수에 따라 판매 가격(할인율)을 유동적으로 다르게 책정하는 시스템입니다.
* **비유:** 대형 마트의 마감 세일과 같습니다. 유통기한(상태)에 따라 할인 스티커를 다르게 붙여 악성 재고를 빠르게 소진시킵니다.

### FIFO by UBCI (상태 기반 선입선출)
* **정의:** 똑같은 등급의 중고 재고가 여러 개 있을 때, 입고일이 가장 오래된 재고를 최우선으로 피킹(출고)하도록 지시하는 알고리즘입니다.
* **비유:** 우유 진열대에서 유통기한이 임박한(가장 먼저 들어온) 우유를 제일 앞줄에 배치해 먼저 팔리게 하는 것과 같습니다.

### Demand Forecasting & Auto-PO (수요 예측 및 자동 발주)
* **정의:** 도서의 출고(판매) 속도를 AI가 분석하여 재고가 바닥나기 전에 출판사(B2B) 측에 자동으로 신간 매입 발주서(PO)를 전송하는 시스템입니다.
* **비유:** 식당 주방장이 밀가루가 떨어지기 전에 알아서 도매상에게 주문 전화를 걸어두는 것과 같습니다.

### Digital Certificate (디지털 품질 보증서)
* **정의:** 출고 시 AI가 검수한 판독 데이터를 바탕으로, 구매자가 모바일에서 즉시 확인할 수 있는 상태 보증서(QR/URL)를 발급하는 시스템입니다.
* **비유:** 중고차 딜러가 발급해주는 성능 점검 기록부와 같습니다. 구매자가 투명하게 상태를 믿고 살 수 있게 돕습니다.

## 🤖 2. 인공지능(AI) 및 알고리즘 용어

### VLM (Vision-Language Model, 시각-언어 모델)
* **정의:** 텍스트와 이미지(시각 데이터)를 동시에 처리하고 이해할 수 있는 멀티모달 AI 모델입니다. (예: GPT-4o)
* **비유:** **'눈 달린 똑똑한 비서'**. 사진을 보여주면 "모서리가 3cm 정도 찢어졌네요"라고 말해줍니다.

### RAG (Retrieval-Augmented Generation, 검색 증강 생성)
* **정의:** AI가 자신이 학습한 과거 지식에만 의존하지 않고, 최신 사내 정책(알라딘 매입 규정 등)이나 매뉴얼 문서를 '실시간으로 검색'해서 읽어본 뒤 정확한 답변을 생성하는 기술입니다.
* **비유:** 시험을 볼 때 기억에만 의존하는 것이 아니라, **'오픈북(Open Book) 테스트'**처럼 책을 직접 찾아보고 답안지를 작성하는 것과 같습니다.

### Knowledge Distillation (지식 증류)
* **정의:** 무겁고 느린 초거대 AI(선생님 모델)의 핵심 지식만을 뽑아내어, 작고 빠른 경량화 AI(학생 모델)에게 주입하는 MLOps 최적화 기법입니다.
* **비유:** 교수가 쓴 두꺼운 전공서적을 학부생이 알기 쉽게 **'요약 노트'**로 압축해서 빠르게 공부하는 것과 같습니다.

### Auto-Labeling (오토 라벨링)
* **정의:** 사람이 일일이 수만 장의 사진에 마우스를 드래그해 정답(찢어짐, 얼룩 등)을 그리는 대신, AI가 1차로 정답 박스를 그려주어 인간의 데이터 구축 시간을 획기적으로 줄이는 기술입니다.
* **비유:** 아이가 스케치북에 색칠을 할 때, 부모님이 미리 **'밑그림 선'**을 다 그려주어 색칠만 하도록 도와주는 것과 같습니다.

### HITL (Human-In-The-Loop, 인간 개입)
* **정의:** 완전 자동화된 AI 파이프라인에서, AI가 판단하기 애매하거나(Confidence 점수 하락) 치명적인 오류가 났을 때 최종 결정권자로 인간 관리자가 개입하는 프로세스입니다.
* **비유:** 비행기가 보통은 자동 조종(Auto-pilot)으로 가지만, 폭우가 쏟아지는 난기류를 만나면 기장이 직접 **'수동 조종간'**을 잡는 것과 같습니다.

### LangGraph Supervisor & Star Topology
* **정의:** 대규모 언어 모델(LLM) 기반의 다중 에이전트 시스템에서, 중앙의 '관리자(Supervisor)' 에이전트가 여러 전문 에이전트들을 별 모양으로 연결하여 통제하고 라우팅하는 구조입니다.
* **비유:** **'종합병원 접수처와 전문의들'**. 환자가 오면 접수처가 증상에 맞게 내과, 외과로 바로 연결해주어 불필요한 대기시간을 없앱니다.

### Fast-track (Auto-refund)
* **정의:** AI 비전 판독 결과 결함이 전혀 없는 'MINT(최상급)' 상태일 경우, 불필요한 규정 대조(Policy)나 검증(Critic) 단계를 건너뛰고 즉시 자동 환불을 승인하는 라우팅 기법입니다.
* **비유:** **'놀이공원 프리패스'**. 아무 문제 없는 깨끗한 책은 복잡한 검사대에서 시간 낭비하지 않고 바로 통과시켜줍니다.

### LLMOps (LangSmith, MemorySaver, Reason Codes)
* **정의:** AI 서비스 운영 고도화 체계. LangSmith는 AI 사고 과정을 추적하고, Reason Codes는 오류를 분류하며, MemorySaver는 관리자 개입(HITL)을 위해 상태를 저장합니다.
* **비유:** **'비행기 블랙박스와 세이브 포인트'**. 사고 원인을 정확히 알 수 있고, 작업 중단 후 관리자 확인이 끝나면 저장한 곳부터 다시 시작합니다.

### Relative Ratio BBox Algorithm (상대적 비율 연산 알고리즘)
* **정의:** 사진만으로는 도서의 실제 2cm 크기를 잴 수 없으므로, '전체 도서 길이(혹은 면적) 대비 훼손 픽셀이 차지하는 비율(%)'을 바탕으로 훼손을 정량 평가하는 알고리즘입니다.
* **비유:** 피자의 절대적인 크기를 자로 재지 않고, "피자 한 조각(8분의 1)"이라는 상대적 비율로 크기를 가늠하는 것과 같습니다.

### 3D Bin Packing (출고 박스 최적화 알고리즘)
* **정의:** 다건 주문 시, 도서들의 부피(가로/세로/두께) 메타데이터를 입체적으로 합산하여 빈 공간이 가장 적은 최적의 택배 박스를 작업자에게 자동 추천하는 알고리즘입니다.
* **비유:** 테트리스 게임처럼 짐의 모양을 돌려보며 가장 작은 상자에 꽉 차게 담아 빈 공간(물류비)을 낭비하지 않는 기술입니다.

## ☁️ 3. 클라우드 및 백엔드(BE) 아키텍처 용어

### FastAPI (패스트에이피아이)
* **정의:** Python으로 작성된 빠르고 모던한 웹 프레임워크로, 비동기 처리 성능이 뛰어나며 AI 파이프라인과 완벽히 호환됩니다.
* **비유:** **'스포츠카를 탄 과학자'**. 인공지능 연산 능력을 갖추고도 트래픽 처리 속도까지 빠릅니다.

### Redis (레디스)
* **정의:** 컴퓨터의 하드디스크가 아닌 메모리(RAM)에 데이터를 저장하여, 일반 DB보다 수백 배 빠른 속도로 데이터를 읽고 쓸 수 있는 '인메모리(In-memory) 데이터 저장소'입니다.
* **비유:** **'요리사의 도마'**. 냉장고(메인 DB)에서 식재료를 매번 꺼내는 대신, 요리사 바로 앞 도마(Redis)에 올려두고 빛의 속도로 칼질하는 것과 같습니다.

### Message Broker (메시지 브로커)
* **정의:** 데이터를 송신하는 쪽과 수신하는 쪽 사이에서 메시지를 임시로 보관하고 안전하게 전달해 주는 미들웨어입니다. (우리는 Redis를 메시지 브로커로 활용합니다.)
* **비유:** **'식당의 주문지 꽂이'**. 홀 직원이 주문을 받아서 주방 주문지 꽂이(Broker)에 꽂아두면, 주방장이 순서대로 뽑아서 요리합니다.

### Celery (셀러리) & Worker (워커)
* **정의:** 메인 API 서버를 멈추지 않게 하기 위해, 무거운 AI 연산이나 시간이 오래 걸리는 작업을 백그라운드에서 대신 처리해 주는 비동기 작업 관리 도구(Celery)와 이를 수행하는 일꾼(Worker)입니다.
* **비유:** **'뒷방의 전문 셰프'**. 카운터 점원(FastAPI)은 손님 주문만 계속 받고, 무거운 요리(AI 검수)는 뒷방에 있는 여러 명의 전문 셰프(Worker)들이 분담해서 처리합니다.

### Polling (폴링)
* **정의:** 클라이언트가 서버에게 "내 작업 끝났어?"라고 일정 시간(예: 3초)마다 주기적으로 물어보며 작업 완료 상태를 확인하는 통신 기법입니다.
* **비유:** 차 뒷좌석에 탄 아이가 아빠에게 3분마다 "우리 다 왔어? 다 왔어?" 하고 계속 물어보는 것과 같습니다.

### Celery/Redis Distributed Queue (비동기 분산 큐 아키텍처)
* **정의:** AI 검수처럼 무거운 작업이 몰렸을 때 서버가 다운되지 않도록, Redis(브로커)에 대기표를 쌓아두고 여러 대의 Celery Worker가 백그라운드에서 하나씩 작업을 꺼내 처리하는 전체 시스템 구조입니다.
* **비유:** **'은행의 번호표 시스템'**. 창구 직원 1명(단일 서버)에게 수십 명이 우르르 몰려가면 난장판이 되지만, 번호표 기계(Redis)에서 번호를 뽑고 대기하면 빈 창구 직원(Worker)들이 순서대로 호출해 안정적으로 업무를 처리합니다.

### AWS S3 (Simple Storage Service)
* **정의:** 아마존(AWS)에서 제공하는 고가용성 클라우드 객체 저장소입니다. 우리 프로젝트에서는 AI가 검수할 도서의 '원본 이미지 사진'들을 무제한으로 보관하고 서빙하는 용도로 사용합니다.
* **비유:** **'거대한 무한 창고'**. 아무리 많은 물건(사진)을 던져 넣어도 공간이 꽉 차지 않는 4차원 마법 주머니와 같습니다.

### E2E Testing (End-to-End Testing)
* **정의:** 사용자가 앱을 켜는 순간(Frontend)부터 백엔드 연동, AI 추론, 데이터베이스 적재까지 전체 흐름이 실제 환경에서 완벽하게 작동하는지 테스트하는 과정입니다.
* **비유:** **'실전 모의고사'**. 개별 과목(유닛)만 치는 게 아니라 실제 수능 시간표와 똑같이 전체를 통합해서 쳐보는 것입니다.

### Kubernetes (K8s) & EKS
* **정의:** 트래픽이 몰리면 자동으로 서버(컨테이너)를 늘려주고, 죽은 서버를 되살려주는 클라우드 오케스트레이션 도구입니다.
* **비유:** 거대한 오케스트라의 **'지휘자'**. 바이올린 소리가 작으면 연주자를 더 부르고, 악기가 고장 나면 즉각 교체합니다.

## 📱 4. 프론트엔드 및 실무/개발 프로세스 용어

### CI/CD (Continuous Integration / Continuous Deployment)
* **정의:** 개발자가 코드를 수정해서 올리면(Push), 시스템이 자동으로 코드를 테스트(CI)하고 실제 서비스 운영 서버에 자동으로 반영 및 배포(CD)해 주는 자동화 파이프라인입니다.
* **비유:** **'자동차 공장의 자동 컨베이어 벨트'**. 기술자가 나사 하나만 조여서 올려두면, 레일을 타고 가면서 불량품 검사(Test)부터 조립, 매장 진열(배포)까지 사람 손 없이 한 번에 끝납니다.

### GitHub Actions (깃허브 액션)
* **정의:** CI/CD 자동화 파이프라인을 쉽게 구축해주는 도구로, 코드를 Github에 올릴 때마다 사전에 설정해둔 명령어(자동 테스트, 서버 배포 등)를 대신 실행해 줍니다.
* **비유:** **'충직한 공장장'**. "내가 코드를 창고(Github)에 갖다 놓을 테니, 이상 없으면 네가 알아서 스토어(서버)에 진열해둬!"라고 지시해 둔 공장장과 같습니다.

### WebRTC & WASM (클라이언트 전처리 기술)
* **정의:** 브라우저 내부에서 실시간으로 후면 카메라를 직접 제어(WebRTC)하고, OpenCV 같은 무거운 C++ 영상 처리 알고리즘을 브라우저에서 즉각 실행(WASM)하여 화질을 압축하고 흔들림을 검출하는 기술입니다.
* **비유:** **'창구 직원의 1차 검문'**. 무거운 서류(사진)를 우편(네트워크)으로 본사에 다 보내기 전에, 창구 직원이 그 자리에서 쓸데없는 내용을 지우고 요약해서 보내는 것과 같습니다.

### Optimistic UI (낙관적 UI)
* **정의:** 사용자가 액션을 취했을 때, 서버의 응답(비동기 폴링 등)을 기다리지 않고 화면상에서는 "이미 성공했다"고 가정하고 즉각적으로 다음 상태를 보여주는 사용자 경험(UX) 최적화 기법입니다. (Jotai 전역 큐를 활용)
* **비유:** **'카페 진동벨'**. 커피(업로드)가 다 나오기를 카운터 앞에서 계속 서서 기다리지 않고, 일단 주문(촬영)이 끝났으니 진동벨만 받고 바로 다음 할 일을 하러 가는 것과 같습니다.
### Git Gatekeeper & Branch Protection Rule
* **정의:** 메인 코드 저장소에 함부로 코드를 덮어쓰지 못하도록, 지정된 리뷰어(Tech PM)의 승인을 받아야만 코드를 병합할 수 있게 제한하는 장치입니다.
* **비유:** **'결재판'**. 회사 금고 비밀번호(메인 코드)를 바꾸지 못하게 반드시 팀장의 승인을 받도록 막아두는 문지기입니다.

### KEDA (Kubernetes Event-driven Autoscaling)
* **정의:** CPU/메모리 같은 시스템 리소스가 아닌, 특정 이벤트(예: Redis 큐에 대기 중인 메시지 개수)를 모니터링하여 Kubernetes 파드(Pod)를 자동으로 늘리거나 줄여주는 오픈소스 스케일러입니다.
* **비유:** **'창고 알바 반장'**. 작업자들이 땀을 흘리는지(CPU) 안 흘리는지 보지 않고, "저기 뜯지 않은 택배 상자(대기열)가 몇 개 남았지?"만 보고 알바생을 더 부를지 퇴근시킬지 결정합니다.

### Exponential Backoff (지수 백오프)
* **정의:** API 통신 실패(예: 429 한도 초과 에러) 시, 즉각적으로 계속 재시도하지 않고 대기 시간을 2초, 4초, 8초 등 기하급수적으로 늘리며 재시도하여 서버 과부하를 막는 네트워크 방어 알고리즘입니다. (`Tenacity` 라이브러리 활용)
* **비유:** **'눈치 빠른 영업사원'**. 거래처 사장님이 바빠서 화를 냈을 때, 1분마다 계속 전화를 거는 게 아니라, 1시간 뒤, 3시간 뒤, 내일 다시 연락하는 식으로 텀을 길게 두고 눈치껏 다시 연락하는 것과 같습니다.

### Multi-API Key Round-Robin (다중 API 키 라운드로빈 풀링)
* **정의:** 트래픽 초과로 단일 API Key가 제한(Rate Limit)에 걸리는 것을 막기 위해, 여러 개의 API Key를 배열(풀)에 등록해 두고 요청마다 순번을 돌아가며(Round-Robin) 사용하는 부하 분산 기법입니다.
* **비유:** **'돌려막기 결제'**. 식당 한도가 10만 원인 법인카드로 30만 원어치 회식을 한 후, 법인카드 3장을 꺼내 10만 원씩 돌아가며 긁어서 결제 한도를 우회하는 것과 같습니다.

### gevent 코루틴 풀 (Coroutine Pool)
* **정의:** Celery 워커가 I/O 대기(API 응답 대기 등) 상태일 때, 기존의 무거운 스레드 생성 방식(Prefork) 대신 매우 가벼운 '그린 스레드(코루틴)' 단위로 컨텍스트 스위칭을 수행하여 단일 워커가 수백 개의 요청을 병렬(논블로킹)로 처리할 수 있게 해주는 라이브러리입니다.
* **비유:** **'멀티태스킹 달인 주방장'**. 냄비에 물을 올려놓고(API 요청) 멍하니 15초 동안 물 끓기를 서서 기다리는(스레드 블로킹) 것이 아니라, 물 끓는 동안 뒤돌아서 파도 썰고 마늘도 다지는(비동기 I/O 전환) 것과 같습니다.

### LPN (License Plate Number) & Matrix Queue (넘버링 매트릭스 바구니)
* **정의:** 입고된 상품을 추적하기 위해 책에 붙이는 바코드(LPN). 만약 라벨 프린터 고장 등 하드웨어 장애(Fail-over)가 발생하면, 시스템이 즉각 '매트릭스 큐 모드'로 전환하여 바코드 대신 화면에 번호(예: A-1)를 띄우고 지정된 번호 바구니에 책을 담게 하는 비상 운영 로직입니다.
* **비유:** **'식당 번호표'**. 진동벨(바코드 기계)이 고장 났을 때, 손님에게 펜으로 "대기번호 5번"이라고 적어준 뒤 "5번 의자에 앉아계세요"라고 육성으로 유도하는 비상 시스템과 같습니다.
