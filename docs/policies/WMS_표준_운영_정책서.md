# 📘 WMS 표준 운영 정책서 (Official SOP)

**시행 일자:** 2026-07-07  
**문서 등급:** 대외 배포용(WMS_docs) / 내부 RAG 참조용 통합본  
**적용 대상:** B2B WMS AI Platform, AI 검수 모듈, 정책 판정 모듈, 판정 검증 모듈, HITL 관리자, 자동 판정 로직  
**목적:** 도서 반품 및 중고 매입 검수 과정에서 AI와 관리자가 동일한 기준으로 검수 상태, 보류 상태, 재고 상태, 최종 처리 액션, 승인 이벤트를 구분하고, `AUTO_PASS`, `REJECT`, `HITL_REQUIRED`, `REFUND_HOLD`, `CLIENT_APPROVAL_REQUIRED`, `DISPUTE_REVIEW`, `QUARANTINE_STOCK`, `SCRAP`, `RETURN_TO_CUSTOMER`, `NORMAL_STOCK`, `DISCOUNT_STOCK`을 판단할 수 있도록 정량적 SLA 기준, 상태 전이 기준, 증빙 기준, 고객사별 정책 적용 기준을 제정한다.

## 제 0 장. 근거 범위 및 해석 원칙

본 문서는 `policy_data_master.yaml`의 외부 플랫폼 정책, 약관, 법령, 가이드라인을 기반으로 작성하되, AI 검수 시스템에서 직접 실행해야 하는 기준은 WMS 내부 운영 기준으로 보완한다.

| 구분                | 문서 반영 방식                                                                                                                          |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| 외부 정책 기반      | 반품 불가 사유, 환불 기한, 배송비 부담, 구성품 누락, 훼손·사용에 따른 가치 감소, 분쟁 시 환불 보류 원칙에 반영한다.                     |
| 법령 기반           | 소비자 책임 훼손, 사용·소비로 인한 가치 감소, 재판매 곤란, 복제 가능 상품 포장 훼손, 표시·광고 불일치 특례, 입증 책임 기준에 반영한다.  |
| 중고 도서 검수 기반 | 물젖음, 곰팡이, 제본 탈착, 심한 오염, 필기 초과, 부록 누락, 불법복제본 기준에 반영한다.                                                 |
| WMS 내부 운영 기준  | AI 촬영 품질, 훼손 면적 비율, 재촬영 횟수, FDS 기간, 격리 재고 기간, HITL 처리 SLA, 고객사 승인 SLA, 관리자 오버라이드 제한에 반영한다. |

① 외부 약관 또는 법령과 WMS 내부 운영 기준이 충돌하는 경우 고객사 계약, 법령, 소비자 보호 기준을 우선한다.

② WMS 내부 운영 기준은 AI와 관리자 판단을 표준화하기 위한 실행 기준으로 적용한다.

③ AI가 판단에 필요한 이미지, 주문 정보, ISBN, 구성품 정보를 확보하지 못한 경우 정상 상태로 추정하지 않는다.

④ 고객 귀책, 배송사 귀책, 물류센터 귀책은 AI가 단독 확정하지 않는다. AI는 후보값을 제시하고, 최종 귀책은 증빙 2개 이상이 서로 일치할 때 관리자 또는 고객사 승인 절차로 확정한다.

⑤ “의심” 상태는 자동 거절의 근거가 아니라 보류 또는 수동 검수의 근거로 사용한다. 단, 실제 훼손, 사용, 누락, 오염이 증빙으로 확인되면 해당 조항에 따라 `REJECT` 또는 재고 제한을 적용한다.

### 제 0조의1. 정책 근거 추적성 및 출처 매핑 원칙

① WMS 표준 운영 정책의 각 조항은 원칙적으로 다음 중 하나 이상의 근거 유형을 가져야 한다.

| 근거 유형      | 의미                                                    | 사용 범위                                                  |
| -------------- | ------------------------------------------------------- | ---------------------------------------------------------- |
| 법령 근거      | 전자상거래법, 택배 표준약관 등 강행 또는 준강행 규범    | 청약철회 제한, 표시·광고 불일치, 입증 책임, 배송·보관 예외 |
| 계약 근거      | 고객사 또는 외부 플랫폼 이용약관·반품·환불 조항         | 반품 가능 기한, 비용 부담, 환불 방식, 특수 상품 예외       |
| 운영정책 근거  | 중고 매입, 검수 등급, 배송 안내, 품질 관리 정책         | 도서 상태 등급, 구성품 누락, 사용 흔적, 배송비 처리        |
| 내부 실행 기준 | AI 모델 한계, 촬영 품질, 재고 격리, HITL SLA, 감사 로그 | 자동 판정 임계값, 상태 전이, 증빙 저장, 오버라이드 제한    |

② 모든 정책 조항은 최종 판정 로그 또는 정책 관리 기록에 최소 1개 이상의 `chunk_id` 또는 내부 기준 근거를 연결한다.

③ 특정 조항의 근거가 외부 플랫폼 리서치 데이터뿐이고 고객사 계약 또는 법령 근거가 확인되지 않은 경우, 해당 조항은 직접 판정 근거가 아니라 WMS 기본 정책 설계 참고 근거로만 사용한다.

④ 고객사별 최종 판정 로그에는 적용된 `Tenant ID`, 정책 문서 ID, 정책 버전, 적용 조항, 검색된 RAG `chunk_id`, 사용한 `authority_rank`, Reason Code를 함께 저장해야 한다.

⑤ 정책 개정 시에는 변경 조항, 변경 전 기준, 변경 후 기준, 변경 사유, 연결된 `chunk_id`, 승인자를 정책 개정 관리 기록에 남긴다.

### 제 0조의2. 정책 권위 레벨 및 RAG 정렬 기준

① `policy_data_master.yaml`의 `authority_level`은 문자열 값만으로 정렬하지 않는다. 시스템은 다음의 `authority_rank`를 내부적으로 부여하고, 숫자가 낮을수록 우선순위가 높은 것으로 처리한다.

| authority_rank | authority_level | 우선순위 의미           | 예시                                              |
| -------------: | --------------- | ----------------------- | ------------------------------------------------- |
|              1 | `Statute`       | 법령 및 강행규정        | 전자상거래법, 공정거래위원회 택배 표준약관        |
|              2 | `Contract`      | 고객사 또는 플랫폼 약관 | 이용약관, 판매자 약관, 반품·환불 약관             |
|              3 | `Policy`        | 운영정책                | 중고 매입 정책, 배송 안내, 환불 처리 정책         |
|              4 | `Guideline`     | 참고 가이드             | 포장 가이드, 상태 등급 가이드, 일반 운영 참고자료 |
|              5 | `Internal`      | WMS 내부 실행 기준      | AI 임계값, SLA, 상태 전이, 모델 검증 기준         |

② RAG 검색 시 사용자의 JWT 또는 요청 컨텍스트에서 `Tenant ID(platform)`을 추출하고, `where={"platform": tenant_id}` 필터를 우선 적용한다.

③ 법령·공통 정책처럼 `platform: Common`인 청크는 고객사 정책과 함께 참조할 수 있으나, 고객사 계약 정책과 충돌하는 경우 법령 및 강행규정 범위에서만 우선한다.

④ `authority_rank`가 같은 문서끼리 충돌하는 경우 최신 정책 버전, 명시적 고객사 계약 여부, 조항 번호 존재 여부, 증빙 적합성 순으로 판단한다.

⑤ `authority_level` 또는 `authority_rank`가 누락된 청크는 자동 판정 근거로 사용할 수 없으며, `HITL_REQUIRED` 또는 `CLIENT_APPROVAL_REQUIRED`로 이관한다.

⑥ RAG 응답에는 최종 판단 근거가 된 청크의 `doc_title`, `clause_ref`, `chunk_id`, `authority_rank`를 내부 로그에 남긴다. 고객 응대 문구에는 내부 `chunk_id`나 FDS 등급을 직접 노출하지 않는다.

## 제 1 장. AI 자동 판정 정책

본 장은 AI 검수 모듈과 정책 판정 모듈가 백엔드 파이프라인에서 즉시 연산할 수 있는 정량 기준이다. AI는 정상 상태가 충분히 입증된 건만 자동 승인하며, 거절 사유가 명확한 경우 `REJECT`, 증빙 또는 귀책이 불명확한 경우 `HITL_REQUIRED` 또는 `REFUND_HOLD`로 이관한다.

### 제 1조. 최종 액션 우선순위

① AI 또는 관리자는 다음 순서에 따라 최종 액션을 결정한다.

| 우선순위 | 최종 액션                            | 의미                         |
| -------- | ------------------------------------ | ---------------------------- |
| 1        | `CLIENT_APPROVAL_REQUIRED`           | 고객사 승인 필요             |
| 2        | `DISPUTE_REVIEW`                     | 고객 이의제기 또는 분쟁 검토 |
| 3        | `REJECT`                             | 반품, 환불, 매입 거절        |
| 4        | `REFUND_HOLD`                        | 환불 보류                    |
| 5        | `HITL_REQUIRED`                      | 관리자 수동 검수 필요        |
| 6        | `QUARANTINE_STOCK`                   | 격리 재고 지정               |
| 7        | `AUTO_PASS`                          | 자동 승인                    |
| 8        | `NORMAL_STOCK` 또는 `DISCOUNT_STOCK` | 재고 편입                    |

② 고객사 계약, 법령, 소비자 분쟁, 고액 환불이 연계된 경우에는 다른 조건보다 `CLIENT_APPROVAL_REQUIRED`를 우선 적용한다.

③ 고객 이의제기가 접수된 건은 `DISPUTE_REVIEW`로 전환하고 자동 환불, 자동 거절 확정, 자동 폐기, 자동 재고 편입을 중단한다.

④ 명확한 거절 조건이 1개라도 확인되면 `AUTO_PASS`, `NORMAL_STOCK`, `DISCOUNT_STOCK`을 적용할 수 없다.

⑤ AI가 판단에 필요한 이미지, 주문 정보, ISBN, 구성품 정보를 확보하지 못한 경우 정상 상태로 추정하지 않는다.

### 제 1조의1. 상태값·처리 액션·승인 이벤트 정의

① WMS는 검수 상태, 보류 상태, 재고 상태, 최종 처리 액션, 승인 이벤트를 구분하여 저장한다.

| 분류           | 값                         | 정의                                            | 사용 기준                                                                                |
| -------------- | -------------------------- | ----------------------------------------------- | ---------------------------------------------------------------------------------------- |
| 검수 상태      | `PENDING_INSPECTION`       | 검수 대기 상태                                  | 입고 또는 촬영 완료 후 AI·관리자 판정 전 단계                                            |
| 검수 상태      | `RECAPTURE_REQUIRED`       | 재촬영 필요 상태                                | 필수 이미지 누락, 품질 부족, 중요 영역 가림 발생 시 적용                                 |
| 검수 상태      | `HITL_REQUIRED`            | 관리자 수동 검수 필요 상태                      | AI 자동 확정이 불가능하거나 고위험 조건이 있는 경우 적용                                 |
| 보류 상태      | `REFUND_HOLD`              | 환불 보류 상태                                  | 귀책, 구성품, 증빙, 정책 충돌이 불명확한 경우 적용                                       |
| 보류 상태      | `CLIENT_APPROVAL_REQUIRED` | 고객사 승인 필요 상태                           | 고액 환불, 고객사 정책 충돌, 폐기·반송·최종 거절 승인 필요 시 적용                       |
| 보류 상태      | `DISPUTE_REVIEW`           | 고객 이의제기 또는 분쟁 검토 상태               | 고객이 판정에 이의를 제기하거나 법적·계약상 검토가 필요한 경우 적용                      |
| 재고 상태      | `QUARANTINE_STOCK`         | 격리 재고 상태                                  | 위생, 정품성, 구성품, 귀책, 분쟁 리스크가 있어 판매 가능 재고와 분리해야 하는 경우 적용  |
| 재고 상태      | `NORMAL_STOCK`             | 정상 재고 상태                                  | 자동 승인 또는 관리자 PASS 후 정상 판매 가능성이 확인된 경우 적용                        |
| 재고 상태      | `DISCOUNT_STOCK`           | 감가 재고 상태                                  | 독서 기능과 구성품은 유지되지만 경미한 외관 하자가 있어 감가 판매만 가능한 경우 적용     |
| 재고 상태      | `SCRAP`                    | 폐기 확정 상태                                  | 재판매·반송·감가 판매가 부적절하거나 고객사 정책상 폐기 대상인 경우 적용                 |
| 최종 처리 액션 | `AUTO_PASS`                | 자동 승인                                       | 모든 자동 승인 조건을 충족한 경우 적용                                                   |
| 최종 처리 액션 | `REJECT`                   | 반품·환불·매입 거절                             | 하드 리미트 또는 고객사 정책상 거절 기준이 증빙으로 확인된 경우 적용                     |
| 최종 처리 액션 | `REFUND_APPROVE`           | 환불 승인                                       | 환불 가능성이 확인되고 보류·분쟁·승인 조건이 해소된 경우 적용                            |
| 최종 처리 액션 | `RETURN_TO_CUSTOMER`       | 고객 반송                                       | 폐기보다 고객 반송이 적합하거나 고객사 정책이 반송을 요구하는 경우 적용                  |
| 최종 처리 액션 | `PARTIAL_REFUND_APPROVED`  | 일부 환불 승인                                  | 해외주문 도서 등 고객사 정책에 따라 수수료·비용을 차감한 차액만 환불하는 경우 적용. 전액 환불 대신 수수료 공제 후 잔액 환불이 명문화된 건에 한해 사용하며, 공제 금액·산출 근거·고객사 승인 또는 정책 조항을 함께 저장한다. |
| 승인 이벤트    | `PASS_OVERRIDE`            | 관리자 또는 고객사 승인에 의한 판정 정정 이벤트 | AI 또는 기존 거절 판정을 수정할 때 발생하는 이벤트이며 독립 재고 상태로 사용하지 않는다. |

② 시스템 DB에서는 현재 상태값과 최종 처리 액션을 분리 저장한다. 예를 들어 `DISCOUNT_STOCK`은 재고 상태이고, `PASS_OVERRIDE`는 상태가 아니라 승인 이벤트다.

③ 승인 이벤트가 발생한 경우 기존 상태를 직접 삭제하지 않고, 기존 상태, 승인 이벤트, 변경 후 상태, 승인자, 승인 사유, 적용 정책 조항을 별도 로그로 저장한다.

### 제 1조의2. 상태 전이(State Transition) 기준

① 상태 전이는 AI 검수 모듈과 정책 판정 모듈가 계속 대화를 주고받기 위해 필요한 개념이 아니라, WMS가 하나의 검수 건을 어떤 상태에서 어떤 상태로 이동시킬 수 있는지를 제한하는 시스템 통제 기준이다.

② AI 검수 모듈, 정책 판정 모듈, 판정 검증 모듈는 최종 액션 후보와 사유를 제안할 수 있으나, 실제 상태 변경은 WMS Orchestrator 또는 백엔드 상태 관리 모듈이 수행한다.

③ 모든 상태 변경은 이전 상태, 변경 상태, 변경 트리거, 변경 주체, 변경 시각, 적용 정책 조항, Reason Code를 함께 저장해야 한다.

| 현재 상태                  | 원칙적으로 허용되는 다음 상태                                                                                                       | 예외 전이 가능 조건                                                                                      | 금지되는 전이 및 통제 기준                                                                   |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| `PENDING_INSPECTION`       | `AUTO_PASS`, `RECAPTURE_REQUIRED`, `HITL_REQUIRED`, `REJECT`, `REFUND_HOLD`, `CLIENT_APPROVAL_REQUIRED`, `QUARANTINE_STOCK`         | 고객사 긴급 승인 또는 시스템 장애 복구 시 상위 승인 후 예외 처리                                         | 증빙 없이 `NORMAL_STOCK`, `DISCOUNT_STOCK`, `SCRAP`으로 직접 전이 금지                       |
| `RECAPTURE_REQUIRED`       | `AUTO_PASS`, `HITL_REQUIRED`, `REJECT`, `REFUND_HOLD`, `CLIENT_APPROVAL_REQUIRED`                                                   | 재촬영 불가 사유가 고객사 승인으로 인정된 경우 HITL 생략 가능                                            | 재촬영 이미지 또는 관리자 사유 없이 `AUTO_PASS` 금지                                         |
| `AUTO_PASS`                | `NORMAL_STOCK`, `REFUND_APPROVE`, `DISPUTE_REVIEW`                                                                                  | 사후 오류 확인 시 `HITL_REQUIRED` 또는 `CLIENT_APPROVAL_REQUIRED`로 정정 가능                            | 고객 이의제기, 사후 오류, 정정 로그 없이 `REJECT`로 직접 변경 금지                           |
| `HITL_REQUIRED`            | `REJECT`, `REFUND_HOLD`, `CLIENT_APPROVAL_REQUIRED`, `QUARANTINE_STOCK`, `NORMAL_STOCK`, `DISCOUNT_STOCK`, `PARTIAL_REFUND_APPROVED` | `PASS_OVERRIDE` 이벤트 발생 시 승인 로그 저장 후 `NORMAL_STOCK`, `DISCOUNT_STOCK`, `REFUND_APPROVE`, `PARTIAL_REFUND_APPROVED` 가능(단, 수수료 차감 근거 및 정책 조항 저장 필수) | 관리자 검수 기록 없이 최종 상태 확정 금지                                                    |
| `REFUND_HOLD`              | `HITL_REQUIRED`, `CLIENT_APPROVAL_REQUIRED`, `REJECT`, `REFUND_APPROVE`, `PARTIAL_REFUND_APPROVED`, `DISPUTE_REVIEW`, `RETURN_TO_CUSTOMER`, `QUARANTINE_STOCK` | 장기 보류 해소 시 상위 승인 후 최종 액션 확정 가능. 해외주문 도서 단순 변심 건에서 수수료 차감 합의 시 `PARTIAL_REFUND_APPROVED` 전이 가능 | 보류 해제 사유 없이 자동 환불 또는 재고 편입 금지. `PARTIAL_REFUND_APPROVED` 전이 시 차감 금액·산출 근거 없이 적용 금지 |
| `CLIENT_APPROVAL_REQUIRED` | `REJECT`, `REFUND_APPROVE`, `PARTIAL_REFUND_APPROVED`, `RETURN_TO_CUSTOMER`, `SCRAP`, `QUARANTINE_STOCK`, `NORMAL_STOCK`, `DISCOUNT_STOCK`, `DISPUTE_REVIEW`   | 계약상 사전 위임 범위가 명확한 경우 내부 책임자 승인으로 대체 가능. 해외주문 도서 수수료 차감 환불에 대해 고객사 승인 완료 시 `PARTIAL_REFUND_APPROVED` 전이 가능 | 고객사 승인 결과 또는 사전 위임 근거 없이 최종 환불, 폐기, 반송 금지                         |
| `DISPUTE_REVIEW`           | `REJECT`, `REFUND_APPROVE`, `CLIENT_APPROVAL_REQUIRED`, `RETURN_TO_CUSTOMER`, `QUARANTINE_STOCK`                                    | 이의제기 인정 시 `PASS_OVERRIDE` 이벤트 후 `REFUND_APPROVE`, `NORMAL_STOCK`, `DISCOUNT_STOCK` 가능       | 분쟁 검토 완료 전 폐기, 정상 재고 편입, 자동 고객 반송 금지                                  |
| `QUARANTINE_STOCK`         | `HITL_REQUIRED`, `REJECT`, `SCRAP`, `RETURN_TO_CUSTOMER`, `CLIENT_APPROVAL_REQUIRED`, `DISCOUNT_STOCK`, `NORMAL_STOCK`              | 위생 검수 통과, 구성품 확인, 격리 해제 승인 후 판매 가능 재고 전이 가능                                  | 격리 해제 기록 없이 판매 가능 재고 편입 금지                                                 |
| `REJECT`                   | `RETURN_TO_CUSTOMER`, `SCRAP`, `DISPUTE_REVIEW`, `CLIENT_APPROVAL_REQUIRED`                                                         | 정정 로그와 2인 승인 또는 고객사 승인 후 `REFUND_APPROVE`, `NORMAL_STOCK`, `DISCOUNT_STOCK` 가능         | 승인 이벤트 없이 `AUTO_PASS`, `NORMAL_STOCK`, `DISCOUNT_STOCK`, `REFUND_APPROVE`로 변경 금지 |
| `NORMAL_STOCK`             | `DISPUTE_REVIEW`, `QUARANTINE_STOCK`                                                                                                | 사후 클레임 또는 재검수 사유가 증빙으로 확인된 경우 전이 가능                                            | 사후 클레임 또는 재검수 사유 없이 상태 변경 금지                                             |
| `DISCOUNT_STOCK`           | `DISPUTE_REVIEW`, `QUARANTINE_STOCK`, `SCRAP`                                                                                       | 감가 사유가 오분류로 확인된 경우 2인 승인 후 `NORMAL_STOCK` 전이 가능                                    | 감가 사유 삭제 로그 없이 정상 재고 편입 금지                                                 |
| `SCRAP`                    | 없음                                                                                                                                | 폐기 처리 전 단계에서만 고객사 승인으로 보류 상태 복귀 가능                                              | 최종 폐기 후 재고 복구 금지                                                                  |
| `RETURN_TO_CUSTOMER`       | 없음                                                                                                                                | 반송 처리 전 단계에서만 고객사 승인으로 보류 상태 복귀 가능                                              | 반송 확정 후 자동 환불 또는 재고 편입 금지                                                   |

④ 예외 전이는 일반 상태 전이와 별도로 승인 이벤트 로그를 남겨야 하며, 승인 이벤트 로그에는 승인자, 승인 시각, 승인 사유, 근거 증빙, 변경 전 상태, 변경 후 상태를 포함한다.

⑤ `REJECT`에서 `REFUND_APPROVE`, `NORMAL_STOCK`, `DISCOUNT_STOCK`으로 변경하는 경우에는 단일 관리자 권한으로 처리할 수 없으며, 정정 로그와 2인 승인 또는 고객사 승인을 요구한다.

⑥ `QUARANTINE_STOCK`에서 `NORMAL_STOCK` 또는 `DISCOUNT_STOCK`으로 전이하려면 격리 해제 사유, 위생 검수 결과, 구성품 확인 결과, 승인자 ID를 저장해야 한다.

⑦ 상태 전이표에 없는 이동은 시스템상 원칙적으로 차단하며, 예외 처리가 필요한 경우 `CLIENT_APPROVAL_REQUIRED` 또는 상위 관리자 승인 절차를 먼저 거친다.

### 제 1조의3. SLA 기준 시각 및 기한 산정 기준

① SLA는 동일한 용어를 사용하더라도 반품 접수, 물류센터 입고, AI 판정, HITL 배정, 고객사 승인 요청의 시작 시각이 다르므로 다음 기준 시각을 적용한다.

| SLA 대상           | 기준 시각                           | 처리 기한                            | 초과 시 처리                                                     |
| ------------------ | ----------------------------------- | ------------------------------------ | ---------------------------------------------------------------- |
| 반품 접수          | 고객이 반품 신청을 완료한 시각      | 고객의 상품 수령일로부터 **7일 이내** 신청 완료 (단, 플랫폼별 특별약관이나 하자보증 기간은 예외) | 접수 지연 사유 기록                                              |
| 물류센터 입고 검수 | 반품 상품의 입고 스캔 시각          | 영업일 기준 2일 이내 1차 검수        | `HITL_REQUIRED` 또는 관리자 알림                                 |
| AI 자동 판정       | 필수 촬영 이미지 업로드 완료 시각   | 시스템 처리 즉시 또는 당일 내        | 실패 사유 기록 후 `HITL_REQUIRED`                                |
| 재촬영 요청        | `RECAPTURE_REQUIRED` 상태 생성 시각 | 고객사 정책 또는 내부 안내 기한 적용 | 2회 실패 시 `HITL_REQUIRED`                                      |
| HITL 검수          | `HITL_REQUIRED` 상태 생성 시각      | 영업일 기준 2일 이내                 | `REFUND_HOLD` 또는 책임자 알림                                   |
| 환불 보류          | `REFUND_HOLD` 상태 생성 시각        | 영업일 기준 3일 이내 1차 검토        | 7일 초과 시 `CLIENT_APPROVAL_REQUIRED`, 14일 초과 시 책임자 알림 |
| 고객사 승인        | 승인 요청 발송 시각                 | 영업일 기준 7일 이내 1차 응답 확인   | 14일 2차 알림, 30일 장기 보류 검토                               |
| 고객 이의제기      | `DISPUTE_REVIEW` 상태 생성 시각     | 영업일 기준 3일 이내 1차 검토        | 책임자 알림 및 증빙 보존 연장                                    |
| 격리 재고 이동     | `QUARANTINE_STOCK` 상태 생성 시각   | 24시간 이내 물리적 격리              | 작업자 및 관리자 알림                                            |
| 장기 격리 재고     | 격리 상태 생성 시각                 | 30일 이내 처리 방향 확정             | 고객사 승인 또는 내부 폐기 검토                                  |

② 영업일 기준은 토요일, 일요일, 법정공휴일을 제외한다. 단, 위생 위험 격리 재고의 물리적 이동 기한 24시간은 달력 시간 기준으로 산정한다.

③ SLA 기한 산정에 필요한 기준 시각이 누락된 건은 자동 환불, 자동 승인, 정상 재고 편입 대상에서 제외한다.

④ SLA 초과가 발생한 경우 시스템은 지연 사유, 현재 상태, 책임 부서, 다음 조치 기한을 기록해야 한다.

### 제 2조. AUTO_PASS 최소 허용 기준

① `AUTO_PASS`는 아래 조건을 모두 충족한 경우에만 허용한다.

| 구분              | 자동 승인 허용 기준                                                                                                                           |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| 이미지 품질       | 모든 필수 이미지가 `VALID` 상태일 것                                                                                                          |
| 촬영 세트         | 표지, 책등, 책배, 바코드 또는 ISBN, 내지, 구성품 이미지가 모두 존재할 것                                                                      |
| 상품 식별         | 주문 ISBN과 촬영 ISBN이 정확히 일치할 것                                                                                                      |
| 바코드 판독       | 바코드 또는 ISBN이 정상 판독될 것                                                                                                             |
| 훼손 면적         | 훼손 면적 비율이 `2.0% 이하`일 것                                                                                                             |
| 중요 영역         | 바코드, ISBN, 본문, 제본부, 인증코드 영역에 손상이 없을 것                                                                                    |
| 위생 상태         | 물젖음, 곰팡이, 악취, 끈적임, 음식물 잔여물이 없을 것                                                                                         |
| 내지 상태         | 필기, 밑줄, 낙서, 문제 풀이 흔적이 없을 것                                                                                                    |
| 제본 상태         | 페이지 누락, 페이지 찢김, 제본 파손이 없을 것                                                                                                 |
| 구성품            | `CORE` 및 `AUTH` 구성품이 모두 확인될 것                                                                                                      |
| 인증형 구성품     | 인증코드, 쿠폰, 시리얼 코드가 미사용 상태로 확인될 것                                                                                         |
| FDS 상태          | 최근 `30일 이내` FDS 위험 신호가 없을 것                                                                                                      |
| AI 판정 일치 여부 | AI 검수 모듈, 정책 판정 모듈, 판정 검증 모듈의 추천 최종 액션이 모두 일치할 것                                                                |
| AI 신뢰도         | AI 검수 모듈, 정책 판정 모듈, 판정 검증 모듈의 개별 `confidence_score`가 모두 `0.80 이상`이고, OCR·ISBN 비교 신뢰도가 운영 임계값을 충족할 것 |
| 절차 상태         | 고객 이의제기, 고객사 승인 대기, 환불 보류, 격리 재고 상태가 아닐 것                                                                          |

② 제1항의 조건 중 하나라도 충족하지 못하면 `AUTO_PASS`를 금지한다.

③ 환불 예정액이 `50,000 KRW 이상`인 경우 제1항을 충족하더라도 자동 승인을 취소하고 `HITL_REQUIRED`로 이관한다.

④ 정가 또는 환불 예정액이 `100,000 KRW 이상`인 도서, 희귀본, 절판본, 한정판, 세트 상품, 고객사 전용 사은품 포함 상품은 자동 승인 대상에서 제외한다.

⑤ `AUTO_PASS` 처리 건은 최소 1개의 대표 이미지, ISBN OCR 결과, 적용 정책 조항, 최종 액션 로그가 저장되어야 한다.

⑥ `confidence_score`가 산출되지 않았거나 모듈별 산출 방식이 서로 다른 경우에는 자동 승인을 금지하고 `HITL_REQUIRED`로 이관한다.

⑦ 세 모듈의 최종 액션이 모두 일치하더라도, 개별 신뢰도 중 하나라도 `0.80 미만`이거나 OCR·ISBN 비교가 불명확하면 `AUTO_PASS`가 아니라 `HITL_REQUIRED` 또는 `REFUND_HOLD`로 처리한다.

⑧ 동일 모델·프롬프트 버전에서 `AUTO_PASS` 후 고객 클레임 발생률이 정책 품질 점검 기준을 초과하면 해당 유형의 자동 승인 조건을 즉시 중단하고 Shadow Test 또는 HITL 강화 기준으로 전환한다.

### 제 3조. REJECT 하드 리미트

① 다음 조건 중 하나라도 확인되면 즉시 `REJECT`로 처리한다.

| 구분                | REJECT 기준                                                                                                             |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| 상품 불일치         | 주문 ISBN과 촬영 ISBN이 불일치하거나 반품 상품이 주문 상품과 다른 경우                                                  |
| 식별 불가           | 바코드와 ISBN이 모두 판독 불가능하거나 식별 영역이 훼손된 경우                                                          |
| 정품성 문제         | 불법 복제본, 임의 제본 개조, 도서관·대여점 바코드, 비매품·교사용 도장 등 정품성 또는 판매 가능성이 부정되는 경우        |
| 페이지 누락         | 내지 페이지 누락이 `1페이지 이상` 확인된 경우                                                                           |
| 제본 파손           | 제본 탈착, 페이지 분리, 제본부 벌어짐이 확인된 경우                                                                     |
| 본문 훼손           | 본문 판독이 불가능한 찢김·오염·번짐이 `1곳 이상` 확인된 경우                                                            |
| 일반 도서 사용 흔적 | 일반 도서에서 필기·밑줄·낙서가 `5페이지 초과` 확인되거나, 지우기 어려운 볼펜·매직·형광펜 표시가 본문 영역을 침범한 경우 |
| 문제집 사용 흔적    | 문제집, 수험서, 워크북에서 문제 풀이, 정답 표시, 채점 흔적, 오답 표시가 `1문항 이상` 확인된 경우                        |
| 물젖음              | 내지 `2페이지 이상`에서 물젖음, 종이 울음, 잉크 번짐이 확인된 경우                                                      |
| 곰팡이              | 곰팡이 의심 객체가 `2개 이상` 탐지되거나 물젖음 흔적과 함께 확인된 경우                                                 |
| 악취                | 2차 검수 포함 관리자 검수에서 곰팡이 냄새, 담배 냄새, 음식물 부패 냄새, 반려동물 배설물 냄새가 명확히 확인된 경우       |
| 잔여물              | 표지, 내지, 책배에 끈적임, 음식물, 음료 잔여물이 `1곳 이상` 확인된 경우                                                 |
| 구성품 누락         | `CORE` 구성품이 `1개 이상` 누락된 경우                                                                                  |
| 인증형 구성품 사용  | `AUTH` 구성품이 사용된 사실이 고객사 시스템, 스크래치 노출, 등록 이력, 관리자 확인 중 하나로 명확히 확인된 경우         |
| 고의 훼손           | 출고 이미지, 반품 이미지, 고객 이력 데이터에서 고객 고의 훼손 정황이 확인된 경우                                        |

② `REJECT`는 복수 조건을 요구하지 않는다. 하드 리미트 조건 1개만 충족해도 거절 처리할 수 있다.

③ `AUTH` 구성품의 사용 여부가 불명확한 경우에는 즉시 `REJECT`하지 않고 `REFUND_HOLD` 또는 `HITL_REQUIRED`로 처리한다.

④ `REJECT` 처리된 도서는 정상 재고 또는 감가 재고로 편입할 수 없다.

⑤ `REJECT` 처리 시 Reason Code 1개 이상, 근거 이미지 1개 이상, 적용 정책 조항을 반드시 저장한다.

### 제 4조. 훼손 면적 및 중요 영역 기준

① 훼손 면적은 VLM의 자연어 판단만으로 확정하지 않는다. 도서 영역 분리 결과와 훼손 후보 영역 산출 결과를 함께 사용하여 계산한다.

② 시스템은 도서가 차지하는 영역을 `book_mask_area`로 분리하고, 찢김·오염·찍힘·구김·물젖음 등 훼손 후보 영역을 `total_damage_area`로 산출한다. 세그멘테이션 마스크를 사용할 수 있으면 `damage_mask_area`를 우선 사용하고, 마스크 산출이 어려운 경우 중복 제거된 BBox 면적을 사용한다.

```text
damage_ratio = total_damage_area / book_mask_area
```

③ 훼손 면적 기준은 아래 품질 조건을 충족한 경우에만 자동 판정에 사용한다.

| 측정 전제      | 최소 조건                                                 |
| -------------- | --------------------------------------------------------- |
| 촬영 각도      | 표지 또는 내지가 화면 기준 `15도 이내` 기울기로 촬영될 것 |
| 도서 포함률    | 도서 전체 영역의 `90% 이상`이 화면에 포함될 것            |
| 해상도         | 긴 변 기준 `1200px 이상`일 것                             |
| 가림 여부      | 손, 그림자, 반사광, 물체 가림이 중요 영역에 없을 것       |
| 도서 영역 분리 | `book_mask_area` 산출이 가능할 것                         |
| 훼손 후보 분리 | `damage_area`가 세그멘테이션 또는 BBox로 산출될 것        |

④ 제3항의 측정 전제를 충족하지 못하면 훼손 면적 비율로 `REJECT`를 확정하지 않고 `RECAPTURE_REQUIRED` 또는 `HITL_REQUIRED`로 이관한다.

⑤ 훼손 면적 비율에 따른 처리 기준은 다음과 같다.

| 훼손 면적 비율         | 처리 기준                                                                                                      |
| ---------------------- | -------------------------------------------------------------------------------------------------------------- |
| `0.0%`                 | 다른 결격 사유가 없으면 `AUTO_PASS` 후보로 분류한다.                                                           |
| `0.0% 초과 2.0% 이하`  | 중요 영역 손상이 없고 위생·구성품 문제가 없으면 `AUTO_PASS` 후보로 분류할 수 있다.                             |
| `2.0% 초과 5.0% 이하`  | `AUTO_PASS`를 금지하고 `HITL_REQUIRED`로 이관한다. 독서 기능과 위생 문제가 없으면 감가 재고 후보로만 검토한다. |
| `5.0% 초과 10.0% 이하` | `REJECT`로 처리한다.                                                                                           |
| `10.0% 초과`           | 재판매 불가로 보고 `SCRAP` 또는 `RETURN_TO_CUSTOMER` 대상으로 분류한다.                                        |

⑥ 중요 영역은 면적 비율과 관계없이 손상 `1곳 이상`이 확인되면 `REJECT` 대상으로 본다.

| 중요 영역 유형   | 포함 영역                                             | 처리 기준                                                |
| ---------------- | ----------------------------------------------------- | -------------------------------------------------------- |
| 상품 식별 영역   | 바코드, ISBN, 제목 식별 영역                          | 판독 불가 또는 훼손 확인 시 `REJECT`                     |
| 독서 기능 영역   | 본문 텍스트, 문제 영역, 정답·해설 영역, 페이지 번호   | 판독 방해 손상 `1곳 이상` 확인 시 `REJECT`               |
| 구조 기능 영역   | 제본부, 책등, 페이지 접합부                           | 벌어짐, 탈착, 페이지 분리 확인 시 `REJECT`               |
| 인증·권리 영역   | 인증코드, 쿠폰, 시리얼 코드, 다운로드 코드            | 사용 확인 시 `REJECT`, 사용 여부 불명확 시 `REFUND_HOLD` |
| 구성품 식별 영역 | 별책, 해설지, 세트 일부 권, CD·DVD·USB 등 필수 구성품 | 누락 확인 시 `REJECT`, 식별 불가 시 `HITL_REQUIRED`      |

⑦ AI가 탐지한 훼손 영역이 출판사 디자인, 빈티지 효과, 일러스트, 조명 반사일 가능성이 있으면 `REJECT`로 확정하지 않고 `HITL_REQUIRED`로 이관한다.

⑧ 동일 이미지 안에서 BBox가 중복되는 경우 중복 영역은 한 번만 계산한다.

⑨ `DISCOUNT_STOCK`으로 편입되는 재고는 훼손 면적 및 오염 종류에 따라 다음의 세부 등급을 부여한다.

| 훼손 면적 비율 | 세부 등급 | 상세 기준 | 권장 감가율 |
| --- | --- | --- | --- |
| `2.0% 초과 3.0% 이하` | `GRADE_S` (최상) | 미세한 표지 스크래치, 극미한 눌림 등 기능 무관 손상 | 정가의 10% ~ 15% 감가 |
| `3.0% 초과 4.0% 이하` | `GRADE_A` (상) | 표지의 약간의 구김/접힘, 1~2cm 오염 또는 모서리 해짐 | 정가의 15% ~ 30% 감가 |
| `4.0% 초과 5.0% 이하` | `GRADE_B` (중) | 약간의 변색, 2cm 이하 찢김, 지울 수 있는 희미한 필기(5쪽 이하) | 정가의 30% ~ 50% 감가 |

⑩ WMS 재고 시스템은 부여된 감가 등급(`GRADE_S/A/B`)을 기준으로 고정 할인율 구간을 적용하거나, 수요 예측 모델과 연계한 동적 가격 조정(Dynamic Pricing)을 위한 데이터로 활용해야 한다.

### 제 4조의2. AI 모델 검증 및 배포 기준

① AI 검수 모듈, OCR 모델, 훼손 탐지 모델, 정책 매칭 모델을 변경하거나 신규 배포하는 경우 운영 반영 전 검증을 수행해야 한다.

② 모델 검증은 WMS 프로젝트에서 직접 구축한 내부 사진 데이터셋 `1,000장`을 기준으로 수행한다. 외부 공개 이미지나 타 고객사 이미지는 최종 검증 기준으로 사용하지 않는다.

| 데이터 유형                       | 최소 수량 | 포함 기준                                                             |
| --------------------------------- | --------: | --------------------------------------------------------------------- |
| 정상 도서 및 미사용 도서          |     150장 | 훼손, 필기, 구성품 누락, 바코드 손상이 없는 도서                      |
| 표지 디자인·조명·빈티지 오탐 위험 |     100장 | 표지 디자인, 빈티지 효과, 그림자, 반사광이 훼손처럼 보일 수 있는 도서 |
| 물젖음·곰팡이·오염                |     150장 | 물자국, 종이 울음, 곰팡이 의심, 음식물 또는 음료 잔여물 사례          |
| 필기·밑줄·문제 풀이               |     150장 | 일반 도서 필기, 형광펜, 볼펜, 문제집 풀이, 채점 흔적 사례             |
| 페이지 누락·찢김·제본 파손        |     100장 | 페이지 누락, 페이지 분리, 제본 탈착, 본문 판독 불가 손상 사례         |
| ISBN·바코드·OCR 및 저품질 촬영    |     120장 | 바코드 가림, 흔들림, 저해상도, 기울어진 촬영, ISBN 판독 실패 사례     |
| `CORE`·`AUTH` 구성품 및 세트 상품 |     120장 | 별책, 해설지, 인증코드, 쿠폰, 세트 일부 권 누락 또는 사용 의심 사례   |
| 배송 박스 손상 및 귀책 판단       |     110장 | 박스 찌그러짐, 파손, 침수, 도서 모서리 압착, 배송사 로그 연계 사례    |

③ 내부 사진 데이터셋 `1,000장`은 모델·프롬프트 조정용 `700장`, 검증용 `200장`, 최종 홀드아웃 검증용 `100장`으로 분리한다. 최종 홀드아웃 `100장`은 모델 또는 프롬프트 조정에 사용하지 않는다.

④ 모델 검증 기준은 다음과 같이 적용한다.

| 검증 항목            | 최소 기준                                                                                    | 미충족 시 처리                      |
| -------------------- | -------------------------------------------------------------------------------------------- | ----------------------------------- |
| 하드 리미트 미탐     | 페이지 누락, 인증코드 사용, 불법 복제본, 곰팡이·물젖음 복합 사례 미탐 `0건`                  | 운영 배포 보류                      |
| `AUTO_PASS` 오승인   | 최종 홀드아웃에서 `0건` 목표, 1건 이상 발생 시 해당 유형 자동 승인 금지                      | 원인 분석 후 재검증                 |
| `REJECT` 오거절      | 검증용 200장 기준 기존 운영 기준 대비 `2.0%p 초과` 증가 금지                                 | 샘플 재검수 후 배포 보류            |
| ISBN·바코드 인식     | 주문 ISBN과 촬영 ISBN 비교 오류 `0건` 목표                                                   | OCR 기준 재조정                     |
| 표지 디자인 오탐     | 동일 ISBN 또는 동일 표지 유형 반복 오탐 `3건 이상` 발생 금지                                 | 개선 데이터셋 후보 등록             |
| AI 판정 모듈 간 충돌 | AI 검수 모듈, 정책 판정 모듈, 판정 검증 모듈의 최종 액션 충돌률이 기존 대비 증가하지 않을 것 | 프롬프트 또는 정책 매칭 기준 재검토 |

⑤ 신규 모델은 운영 반영 전 내부 사진 데이터셋 1,000장 기준 검증과 제한적 Shadow Test를 거쳐야 한다. Shadow Test 기간에는 신규 모델 결과를 최종 판정에 직접 사용하지 않고 기존 운영 판정과 비교한다.

⑥ Shadow Test는 최소 `1주일` 또는 운영 검수 `1,000건` 비교 중 먼저 충족되는 기준으로 수행한다. 단, 하드 리미트 미탐 또는 `AUTO_PASS` 오승인이 발생하면 기간 충족 여부와 관계없이 운영 배포를 보류한다.

⑦ 모델 배포 후 `AUTO_PASS` 후 고객 클레임 발생률, `REJECT` 후 이의제기 인정률, AI 오탐률, AI 미탐률이 정책 품질 점검 기준을 초과하면 이전 모델 또는 이전 정책 기준으로 롤백할 수 있다.

⑧ 모든 AI 판정 로그에는 모델명, 모델 버전, 프롬프트 버전, 정책 문서 버전, 판정 시각을 저장해야 한다.

⑨ 신규 모델 또는 프롬프트는 `confidence_score` 산출 방식, OCR 신뢰도 산출 방식, 정책 매칭 점수 산출 방식을 함께 문서화해야 한다. 산출 방식이 문서화되지 않은 모델 결과는 자동 승인 근거로 사용할 수 없다.

⑩ 정책 매칭 모델은 `authority_rank`가 낮은 법령·계약 문서를 우선 검색·인용하는지 검증해야 하며, 고객사 Tenant 필터가 누락된 테스트 케이스가 1건이라도 발생하면 운영 배포를 보류한다.

### 제 5조. 이미지 품질 및 재촬영 기준

① AI는 촬영 이미지를 `VALID`, `LIMITED`, `INVALID`로 분류한다.

| 등급      | 판정 기준                                                                                                            | 처리 기준            |
| --------- | -------------------------------------------------------------------------------------------------------------------- | -------------------- |
| `VALID`   | 도서 전체 영역의 `90% 이상`이 화면에 포함되고, 바코드 또는 ISBN이 식별 가능하며, 핵심 훼손 부위가 가려지지 않은 상태 | AI 자동 판정 허용    |
| `LIMITED` | 도서 전체 영역의 `70% 이상 90% 미만`만 촬영되었거나 일부 정보가 흐릿하지만 육안 검토 가능성이 있는 상태              | `RECAPTURE_REQUIRED` |
| `INVALID` | 도서 전체 영역의 `70% 미만`만 촬영되었거나 바코드, ISBN, 제목이 모두 판독 불가능한 상태                              | `RECAPTURE_REQUIRED` |

② 이미지 품질이 `VALID`인 경우에만 AI 자동 판정을 허용한다.

③ 이미지 품질이 `LIMITED` 또는 `INVALID`이면 `RECAPTURE_REQUIRED`로 처리한다.

④ 동일 사유로 재촬영이 `2회 실패`하면 `HITL_REQUIRED`로 고정한다.

⑤ 동일 고객 또는 작업자가 최근 `30일 이내` 재촬영 요청을 `3회 이상` 발생시키면 FDS 위험 신호로 기록한다.

⑥ 재촬영 요청 시 시스템은 누락된 촬영 부위와 재촬영 사유를 고객 또는 작업자 화면에 명확히 표시해야 한다.

## 제 2 장. 수동 검수 관리자 행동 지침

본 장은 AI가 자동 판정을 유보한 건에 대해 HITL 관리자가 수행해야 하는 필수 검수 절차다. HITL은 자동 승인을 위한 우회 절차가 아니라, 거절, 보류, 고객사 승인 여부를 확정하기 위한 검수 절차다.

### 제 6조. HITL 필수 전환 기준

① 다음 중 하나라도 해당하면 `HITL_REQUIRED`로 이관한다.

| 구분          | HITL 전환 기준                                                                 |
| ------------- | ------------------------------------------------------------------------------ |
| 이미지 품질   | 이미지 품질이 `LIMITED` 또는 `INVALID`인 경우                                  |
| 촬영 누락     | 필수 촬영 이미지가 `1개 이상` 누락된 경우                                      |
| AI 판정 충돌  | AI 검수 모듈, 정책 판정 모듈, 판정 검증 모듈의 추천 최종 액션이 서로 다른 경우 |
| 훼손 불명확   | 훼손 영역이 실제 훼손인지 표지 디자인인지 불명확한 경우                        |
| 귀책 불명확   | 고객, 배송사, 물류센터 중 귀책 주체가 불명확한 경우                            |
| 고액 환불     | 환불 예정액이 `50,000 KRW 이상`인 경우                                         |
| 특수 상품     | 고가 도서, 희귀본, 절판본, 한정판에 해당하는 경우                              |
| 인증형 구성품 | 인증코드 또는 쿠폰 사용 여부가 확인되지 않는 경우                              |
| 고객 이의제기 | 고객이 AI 또는 관리자 판정 결과에 이의를 제기한 경우                           |

② HITL 관리자는 배정 후 `영업일 기준 2일 이내` 1차 판정을 완료해야 한다.

③ `영업일 기준 2일 이내` 판정이 불가능한 경우 `REFUND_HOLD` 또는 `CLIENT_APPROVAL_REQUIRED` 사유를 기록해야 한다.

④ HITL 관리자는 AI 판정을 그대로 승인하기 전에 주문 ISBN, 촬영 ISBN, 핵심 구성품, 훼손 근거 이미지, 적용 정책 조항을 확인해야 한다.

---

### 제 7조. 후각 및 촉각 검수 기준

① 후각 및 촉각 검수는 AI 자동 판정 대상이 아니라 관리자 수동 검수 대상이다.

② 관리자는 도서 내지를 펼쳐 곰팡이 냄새, 담배 냄새, 음식물 부패 냄새, 반려동물 배설물 냄새, 기타 심한 악취를 확인한다.

③ 후각 및 촉각 검수 등급은 다음과 같이 저장한다.

| 등급        | 판정 기준                                                                | 처리 기준                                                    |
| ----------- | ------------------------------------------------------------------------ | ------------------------------------------------------------ |
| `SENSORY_0` | 냄새 또는 촉각 이상 없음                                                 | 다음 검수 진행                                               |
| `SENSORY_1` | 약한 냄새 또는 약한 이질감이 있으나 단일 관리자 판단으로 확정하기 어려움 | `HITL_REQUIRED` 유지 및 2차 검수 요청                        |
| `SENSORY_2` | 곰팡이·담배·부패·배설물 냄새 또는 젖은 촉감이 명확함                     | `REJECT`                                                     |
| `SENSORY_3` | 다른 재고 오염 가능성이 있는 강한 악취, 곰팡이, 음식물 잔여물이 명확함   | `QUARANTINE_STOCK` 후 `SCRAP` 또는 `RETURN_TO_CUSTOMER` 검토 |

④ 제3항의 `SENSORY_2` 또는 `SENSORY_3`은 관리자 ID, 검수 시각, 검수 등급, 근거 이미지, 2차 검수 여부와 함께 저장한다.

⑤ 악취 또는 촉각 이상이 불명확한 경우 단일 관리자 판단만으로 `REJECT`하지 않는다.

---

### 제 8조. 플립 테스트 기준

① 관리자는 책등을 잡고 내지를 약 `3초간` 빠르게 넘기는 플립 테스트를 실시한다.

② 플립 테스트에서 낙서, 형광펜 자국, 볼펜 밑줄, 문제 풀이 흔적, 페이지 찢어짐, 페이지 누락, 제본 불량, 물젖음으로 인한 페이지 부착 중 하나라도 발견되면 `REJECT`로 처리한다.

③ 일반 도서에서 본문을 침범하지 않는 연필 표시가 `1페이지 이하`이고 면적이 해당 페이지의 `1.0% 이하`인 경우에만 고객사 정책에 따라 예외 검토할 수 있다.

④ 문제집, 수험서, 워크북은 연필 표시라도 사용 흔적으로 보고 `REJECT` 처리한다.

⑤ 플립 테스트 결과는 `PASS`, `MINOR_DEFECT`, `REJECT`, `HITL_REQUIRED` 중 하나로 저장한다.

---

### 제 9조. AI 오탐 오버라이드 제한 기준

① 관리자는 AI가 탐지한 BBox 영역을 실제 도서와 대조한다.

② AI 탐지 영역이 출판사 디자인, 빈티지 효과, 인쇄 질감, 일러스트, 조명 반사 중 하나임이 명확하고 실제 도서에 훼손이 없으며 바코드, ISBN, 본문, 제본부, 인증코드 영역에 손상이 없는 경우에만 `PASS_OVERRIDE`를 허용한다.

③ `PASS_OVERRIDE` 처리 시 관리자 근거 이미지 `1개 이상`, 오버라이드 사유, 관리자 ID, 적용 정책 조항을 저장해야 한다.

④ 다음 건은 단일 관리자 권한으로 `PASS_OVERRIDE`할 수 없다.

| 제한 대상                         | 처리 기준                              |
| --------------------------------- | -------------------------------------- |
| 환불 예정액 `50,000 KRW 이상`     | 고객사 승인 또는 상위 관리자 승인 필요 |
| 고가 도서, 희귀본, 절판본, 한정판 | 고객사 승인 필요                       |
| FDS 위험 계정                     | 단일 관리자 승인 불가                  |
| 인증코드 포함 상품                | 사용 여부 확인 전 승인 불가            |
| 고객사 정책 충돌 건               | 고객사 승인 필요                       |
| 고객 이의제기 진행 건             | 분쟁 검토 완료 전 승인 불가            |
| 법적 검토 가능성이 있는 건        | 법무 또는 고객사 승인 필요             |

⑤ 동일 관리자의 `PASS_OVERRIDE` 비율이 최근 `30일 기준 5.0% 초과`이면 내부 감사 대상으로 분류한다.

⑥ 동일 관리자의 `PASS_OVERRIDE`가 최근 `30일 이내 10건 이상` 발생하면 비율과 관계없이 샘플 감사를 수행한다.

---

## 제 3 장. FDS 및 반복 악용 방어 정책

본 장은 허위 반품, 고의 훼손, 반복 악용을 통제하기 위한 스케줄러 기반 제재 기준이다. FDS 등급은 단독으로 `REJECT` 사유가 되지 않으며, 자동 승인 제외와 수동 검수 강화를 위한 내부 위험 신호로만 사용한다.

### 제 10조. FDS 위험 계정 판단 기준

① 특정 바이어가 최근 `30일 이내` 출고 당시 `MINT` 등급이었던 도서를 훼손 사유로 `3회 이상` 반품한 경우 `FDS_HIGH_RISK`로 분류한다.

② 다음 조건 중 `2개 이상` 충족하면 `FDS_WATCH`로 분류한다.

| 조건                | 판단 기준                                           |
| ------------------- | --------------------------------------------------- |
| 훼손 사유 반복      | 최근 `30일 이내` 훼손 사유 반품 `2회 이상`          |
| 동일 ISBN 반복      | 동일 ISBN 반품 `2회 이상`                           |
| 동일 카테고리 집중  | 동일 카테고리 반품 비율 `50.0% 이상`                |
| 구성품 누락 반복    | 구성품 누락 반품 `2회 이상`                         |
| 인증코드 악용 의심  | 인증코드 사용 후 반품 의심 `1회 이상`               |
| 고가 도서 반복      | 고가 도서 반품 `2회 이상`                           |
| 사유 불일치 반복    | 고객 반품 사유와 AI 검수 결과 불일치 `2회 이상`     |
| 재촬영 실패 반복    | 재촬영 요청 `2회 이상` 실패                         |
| 상태 등급 하락 반복 | MINT 출고 도서가 FAIR 이하로 반품된 사례 `2회 이상` |

③ `FDS_WATCH` 계정은 Fast-track 자동 승인에서 제외한다.

④ `FDS_HIGH_RISK` 계정은 마지막 위험 이벤트 발생일로부터 `6개월간` 모든 반품, 환불, 중고 매입 건을 `HITL_REQUIRED`로 배정한다.

⑤ `FDS_HIGH_RISK` 계정에서 구성품 누락, 인증코드 사용, 물젖음, 필기, 페이지 누락 중 하나가 확인되면 해당 훼손 사유에 따라 `REJECT`로 처리한다.

⑥ FDS 등급은 고객에게 직접 고지되는 제재 명칭으로 사용하지 않는다. 외부 안내 문구는 “추가 검수 필요”, “증빙 확인 필요”, “고객사 승인 필요” 등 중립 표현을 사용한다.

---

### 제 10조의2. FDS 식별 키 및 오탐 방지 기준

① FDS는 고객 ID를 기본 식별 키로 사용한다.

② 동일 배송지, 동일 연락처, 동일 결제수단, 동일 디바이스, 동일 IP, 동일 반품 패턴은 보조 식별 신호로만 사용한다. 보조 식별 신호만으로 고객을 동일 계정으로 확정하거나 제재하지 않는다.

③ FDS 식별 키는 다음 기준에 따라 적용한다.

| 식별 키               | 적용 수준      | 사용 기준                                                                      |
| --------------------- | -------------- | ------------------------------------------------------------------------------ |
| 고객 ID               | 기본 기준      | 동일 고객의 반복 반품, 반복 훼손, 반복 구성품 누락 판단에 사용                 |
| 동일 연락처           | 보조 기준      | 고객 ID가 다르더라도 반복 패턴 확인용으로만 사용                               |
| 동일 배송지           | 보조 기준      | 가족, 기숙사, 회사, 학교 등 다중 사용자 가능성을 고려하여 단독 제재 금지       |
| 동일 결제수단         | 보조 기준      | 부정 사용 의심 보조 신호로만 사용                                              |
| 동일 디바이스 또는 IP | 강한 보조 기준 | 개인정보 및 접속 환경 영향을 고려하여 단독 확정 금지                           |
| 기관·법인 계정        | 별도 세그먼트  | 학교, 학원, 도서관, 법인 구매는 일반 개인 고객 FDS 기준을 그대로 적용하지 않음 |

④ 배송사 귀책, 물류센터 귀책, 동일 로트 상품 하자, 고객사 승인 예외가 확인된 건은 FDS 위험 이벤트 산정에서 제외하거나 완화 사유로 기록한다.

⑤ FDS 식별에 사용되는 연락처, 결제수단, 디바이스, IP 정보는 원문을 직접 노출하지 않고 해시 또는 비식별 키로 저장한다.

⑥ FDS 등급으로 인해 자동 승인 제외 또는 추가 검수가 반복되는 고객이 이의를 제기한 경우, 내부 위험 용어를 노출하지 않고 추가 검수 사유와 필요한 증빙 중심으로 안내한다.

### 제 11조. FDS 제재 및 완화 기준

① `FDS_WATCH` 계정은 마지막 위험 이벤트 발생일로부터 `3개월간` 유지한다.

② `FDS_HIGH_RISK` 계정은 마지막 위험 이벤트 발생일로부터 `6개월간` 유지한다.

③ FDS 위험 계정에는 Fast-track 자동 승인 제외, 자동 환불 제외, 자동 매입 승인 제외, 구성품 포함 상품 반품 시 필수 HITL 배정, 인증코드 포함 상품 반품 시 `REFUND_HOLD`, 반복 훼손 반품 시 고객사 승인 절차를 적용한다.

④ 다음 사유가 증빙으로 확인되면 FDS 제재를 완화할 수 있다.

| 완화 사유           | 완화 기준                                                       |
| ------------------- | --------------------------------------------------------------- |
| 배송사 귀책 파손    | 배송사 사고 로그 또는 외부 포장 손상 증빙이 존재하는 경우       |
| 물류센터 출고 오류  | 출고 전 검수 이미지 또는 작업 로그에서 오류가 확인된 경우       |
| 동일 로트 상품 하자 | 동일 ISBN 또는 동일 로트에서 유사 하자가 `3건 이상` 확인된 경우 |
| 고객사 예외 승인    | 고객사 승인 로그가 저장된 경우                                  |
| 관리자 오분류 확인  | 정정 로그와 승인자 정보가 저장된 경우                           |
| 기관 구매 계정      | 학교, 학원, 도서관, 법인 등 대량 구매 목적이 확인된 경우        |

⑤ `FDS_HIGH_RISK` 계정이 최근 `90일간` 추가 위험 이벤트 없이 모든 HITL 검수를 통과하면 `FDS_WATCH`로 완화할 수 있다.

⑥ 제재 완화 시 관리자 ID, 완화 사유, 증빙 이미지, 승인자를 저장한다.

---

## 제 4 장. 귀책 판단 및 환불 보류 정책

본 장은 훼손 발생 주체를 고객, 배송사, 물류센터, 불명확 상태로 분류하고 환불 승인 여부를 방어적으로 판단하기 위한 기준이다.

### 제 12조. 귀책 주체 분류 기준

① 훼손 발생 주체는 `CUSTOMER_FAULT`, `CARRIER_FAULT`, `WAREHOUSE_FAULT`, `FAULT_UNKNOWN`으로 분류한다.

② AI는 귀책 주체를 최종 확정하지 않고 후보값으로만 제시한다.

③ 최종 귀책 판단은 관리자 검수 결과, 출고 이미지, 반품 이미지, 배송 증빙, 고객사 정책을 종합하여 결정한다.

④ 귀책 주체가 불명확한 경우 정상 환불을 진행하지 않고 `REFUND_HOLD`로 처리한다.

⑤ 귀책 판단은 단일 조건으로 확정하지 않는다. 단, 고객 고의 훼손, 인증코드 사용 확인, 페이지 누락, 불법 복제본처럼 독립적으로 거절 가능한 하드 리미트는 제3조를 우선 적용한다.

---

### 제 12조의2. 증빙 등급 및 우선순위 기준

① 귀책 판단, 거절, 환불 보류, 고객사 승인, 오버라이드에는 증빙 등급을 적용한다.

| 증빙 등급 | 증빙 유형                                                                                                | 신뢰도    | 사용 기준                                                               |
| --------- | -------------------------------------------------------------------------------------------------------- | --------- | ----------------------------------------------------------------------- |
| S등급     | 고객사 시스템 로그, 인증코드 사용 이력, 배송사 사고 로그, 물류센터 작업 로그, 주문·결제·출고 시스템 로그 | 매우 높음 | 귀책 확정, 하드 리미트 확정, 고객사 승인 요청의 핵심 증빙으로 사용 가능 |
| A등급     | 출고 검수 이미지, 반품 입고 이미지, 기준 스티커 또는 눈금자를 포함한 손상 측정 이미지                    | 높음      | 이미지 품질 조건을 충족한 경우 핵심 증빙으로 사용 가능                  |
| B등급     | 고객 제출 이미지, 관리자 HITL 검수 기록, 후각·촉각 검수 등급, OCR 결과, 작업자 촬영 로그                 | 중간      | S등급 또는 A등급 증빙을 보조하거나 HITL 판단 근거로 사용                |
| C등급     | 고객 반품 사유 텍스트, FDS 이력, 재촬영 실패 이력, 저품질 이미지, 상담 메모                              | 낮음      | 단독으로 귀책 확정 또는 `REJECT` 확정에 사용할 수 없음                  |

② 고객 귀책, 배송사 귀책, 물류센터 귀책을 확정하려면 S등급 또는 A등급 증빙 1개 이상과 B등급 이상 증빙 1개 이상이 서로 일치해야 한다.

③ A등급 이미지는 촬영 품질이 `VALID`이거나 손상 측정에 필요한 기준 물체가 포함된 경우에만 핵심 증빙으로 사용할 수 있다. 촬영 품질이 낮거나 중요 영역이 가려진 이미지는 B등급 또는 C등급으로 낮춰 적용한다.

④ S등급 또는 A등급 증빙이 없는 경우에는 귀책을 확정하지 않고 `FAULT_UNKNOWN`, `REFUND_HOLD`, `CLIENT_APPROVAL_REQUIRED` 중 하나로 처리한다.

⑤ C등급 증빙은 FDS 위험 신호, HITL 배정, 재촬영 요청, 추가 증빙 요청의 근거로 사용할 수 있으나 단독으로 환불 거절, 고객 귀책 확정, 폐기 확정에 사용할 수 없다.

⑥ 증빙 간 내용이 충돌하는 경우 가장 강한 증빙 하나를 임의로 선택하지 않고 `HITL_REQUIRED` 또는 `DISPUTE_REVIEW`로 이관한다.

### 제 13조. 고객 귀책 추정 기준

① 다음 조건 중 `2개 이상` 충족하면 `CUSTOMER_FAULT`로 추정한다. 단, 제3조의 `REJECT` 하드 리미트에 해당하는 훼손이 확인되면 귀책 추정과 별개로 `REJECT`를 우선 적용한다.

| 조건                    | 정량 판단 기준                                                                                            |
| ----------------------- | --------------------------------------------------------------------------------------------------------- |
| 일반 도서 사용 흔적     | 필기, 밑줄, 낙서, 접힘 표시가 `3페이지 이상` 확인되거나, 한 페이지 본문 영역의 `10.0% 이상`을 침범한 경우 |
| 문제집·수험서 사용 흔적 | 문제 풀이, 정답 표시, 채점 흔적, 오답 표시, 해설지 필기가 `1문항 이상` 확인된 경우                        |
| 인증형 구성품 문제      | 인증코드, 쿠폰, 시리얼 코드, 온라인 강의 등록권이 사용·스크래치·노출되었거나 `1개 이상` 누락된 경우       |
| 핵심 구성품 누락        | 별책, 해설지, 세트 일부 권, CD·DVD·USB 등 `CORE` 구성품이 `1개 이상` 누락된 경우                          |
| 내부 훼손               | 외부 박스 손상 증빙 없이 본문, 내지, 제본부, 책등 중 `1곳 이상` 훼손된 경우                               |
| 등급 하락               | 출고 당시 `MINT`였으나 반품 입고 시 `FAIR 이하`로 하락한 경우                                             |
| 사유 불일치             | 고객 반품 사유는 단순변심 또는 오배송이나 실제 검수 결과 사용 흔적·훼손·구성품 누락이 확인된 경우         |
| 반복 훼손               | 동일 고객에게서 유사 훼손 반품이 최근 `30일 이내 2회 이상` 반복된 경우                                    |
| 신고 지연               | 고객이 수령 후 `48시간 초과` 시점에 파손 또는 훼손 사유 반품을 접수한 경우                                |
| 재촬영 실패             | 재촬영 요청을 `2회 이상` 실패하거나 바코드, 내지, 구성품 등 핵심 부위를 반복 누락한 경우                  |

② `CUSTOMER_FAULT`로 추정된 건은 즉시 환불하지 않고 `REFUND_HOLD`로 처리한다.

③ `CUSTOMER_FAULT`로 추정된 건에서 물젖음, 필기, 문제 풀이, 구성품 누락, 인증코드 사용, 페이지 누락, 제본 탈착 중 하나가 확인되면 `REJECT`로 처리할 수 있다.

④ 고객 귀책으로 확정하려면 출고 이미지, 반품 이미지, 고객 사유, 촬영 로그, 검수 로그 중 `2개 이상`의 증빙이 서로 일치해야 한다.

⑤ 수령 후 `48시간 초과` 신고는 단독으로 고객 귀책 확정 사유가 될 수 없다. 고객 귀책 확정에는 제1항의 다른 조건 또는 증빙 불일치가 함께 확인되어야 한다.

### 제 14조. 배송사 귀책 추정 기준

① 다음 조건 중 `2개 이상` 충족하면 `CARRIER_FAULT`로 추정한다. 단, 상품 자체가 재판매 불가 상태이면 배송사 귀책 여부와 관계없이 정상 재고 편입은 금지한다.

| 조건               | 정량 판단 기준                                                                          |
| ------------------ | --------------------------------------------------------------------------------------- |
| 외부 포장 찌그러짐 | 배송 박스 모서리 또는 면에 깊이 `10mm 이상`의 찌그러짐이 `1곳 이상` 확인된 경우         |
| 외부 포장 파손     | 박스 찢김, 터짐, 구멍, 테이프 파단이 길이 `20mm 이상` 또는 `1곳 이상` 확인된 경우       |
| 침수 증빙          | 박스 젖음, 물자국, 침수 얼룩이 `10㎠ 이상` 확인되거나 배송 중 침수 로그가 있는 경우     |
| 충격 방향 일치     | 도서 모서리 압착·찍힘 위치가 외부 박스 손상 위치와 같은 면 또는 같은 모서리에 있는 경우 |
| 신고 시간          | 고객이 수령 후 `24시간 이내` 파손을 신고하고 고객 제출 이미지가 존재하는 경우           |
| 사용 흔적 없음     | 내지 필기, 문제 풀이, 인증코드 사용, 구성품 누락 없이 외관 충격 손상만 존재하는 경우    |
| 위치 일치          | 여러 권 중 박스 외곽에 위치한 도서에서만 손상이 확인되는 경우                           |
| 배송 로그          | 택배사 사고 접수, 배송 예외, 재포장, 파손 접수 로그 중 `1개 이상` 존재하는 경우         |

② `CARRIER_FAULT`로 추정되는 경우 고객 귀책으로 단정하지 않는다.

③ 배송사 귀책 가능성이 있더라도 상품 상태가 물젖음, 곰팡이, 악취, 페이지 누락, 제본 탈착에 해당하면 정상 재고로 편입하지 않는다.

④ 배송사 귀책 건은 고객사 계약 기준에 따라 환불, 교환, 배송사 클레임, 고객사 승인 중 하나로 처리한다.

⑤ 배송사 귀책으로 확정하려면 외부 포장 이미지, 반품 입고 이미지, 고객 신고 시각, 배송사 로그 중 `2개 이상`의 증빙이 서로 일치해야 한다.

⑥ 외부 포장 손상 측정을 위해 작업자는 박스 전체 사진 `1장 이상`, 손상 부위 근접 사진 `1장 이상`, 도서 손상 부위 사진 `1장 이상`을 저장해야 한다.

⑦ 찌그러짐 깊이 또는 파손 길이를 측정해야 하는 경우 기준 스티커, 눈금자, 표준 촬영 가이드 중 하나를 사용한다. 기준 물체 없이 촬영된 이미지는 배송사 귀책 확정 증빙으로 단독 사용할 수 없다.

### 제 15조. 물류센터 귀책 추정 기준

① 다음 조건 중 `2개 이상` 충족하면 `WAREHOUSE_FAULT`로 추정한다.

| 조건         | 판단 기준                                                  |
| ------------ | ---------------------------------------------------------- |
| 출고 전 훼손 | 출고 전 검수 이미지에 이미 훼손이 존재함                   |
| 로그 불일치  | 포장 전 검수 로그와 출고 상태가 불일치함                   |
| 로트 반복    | 동일 로트 또는 동일 ISBN에서 유사 훼손이 `3회 이상` 반복됨 |
| 작업 예외    | 피킹, 패킹, 보관 단계에서 예외 이벤트가 기록됨             |
| 보관 이슈    | 보관 구역의 습도, 침수, 오염 이슈가 기록됨                 |
| 작업 누락    | 작업자 검수 누락 또는 스캔 누락이 확인됨                   |

② `WAREHOUSE_FAULT`로 추정되는 경우 고객에게 귀책을 전가하지 않는다.

③ 동일 유형의 물류센터 귀책이 최근 `30일 이내 3회 이상` 반복되는 경우 해당 SKU 또는 로트는 자동 출고 대상에서 제외한다.

④ 물류센터 귀책으로 확정된 건은 고객사 계약 기준에 따라 환불, 교환, 내부 손실 처리, 재발 방지 조치 중 하나로 처리한다.

### 제 16조. 환불 보류 기준

① 다음 중 하나라도 해당하면 즉시 환불하지 않고 `REFUND_HOLD`로 처리한다.

| 구분             | 환불 보류 기준                                             |
| ---------------- | ---------------------------------------------------------- |
| 귀책 불명확      | 고객, 배송사, 물류센터 중 귀책 주체가 불명확한 경우        |
| 사유 불일치      | 고객 반품 사유와 AI 검수 결과가 불일치하는 경우            |
| 인증형 구성품    | 인증코드, 쿠폰, 시리얼 코드 사용 여부가 확인되지 않는 경우 |
| 특수 상품        | 고가 도서, 희귀본, 절판본, 한정판인 경우                   |
| 정책 충돌        | 고객사 정책과 WMS 자체 정책이 충돌하는 경우                |
| 배송 파손 의심   | 배송 중 파손 여부 확인이 필요한 경우                       |
| FDS 위험         | FDS 위험 계정의 반품 건인 경우                             |
| 증빙 부족        | 증빙 이미지가 부족한 경우                                  |
| 이의제기         | 고객이 판정 결과에 이의를 제기한 경우                      |
| 세트 구성 불명확 | 세트 상품의 일부 구성 누락 여부가 불명확한 경우            |

② `REFUND_HOLD` 상태에서는 자동 환불, 자동 재고 편입, 자동 폐기, 자동 감가 판매, 자동 고객 반송을 금지한다.

③ `REFUND_HOLD`는 `REFUND_HOLD` 상태 생성 시각으로부터 `영업일 기준 3일 이내` 관리자 1차 검토를 완료해야 한다.

④ `REFUND_HOLD`가 `영업일 기준 7일`을 초과하면 `CLIENT_APPROVAL_REQUIRED`로 자동 승격한다.

⑤ `REFUND_HOLD` 해제 시 해제 사유, 승인자, 적용 정책 조항, 최종 액션을 기록한다.

⑥ `REFUND_HOLD`가 `영업일 기준 14일`을 초과하면 내부 책임자에게 장기 보류 알림을 발송한다.

## 제 4장의2. 환불 수단, 배송비 부담 및 특수상품 예외 정책

본 장은 `policy_data_master.yaml`에 포함된 결제수단별 환불 처리, 배송비 귀책, 해외주문 및 특수 상품군 제한 기준을 WMS 내부 처리 기준으로 표준화하기 위한 조항이다. 단, 실제 환불 방식과 비용 부담은 고객사 계약, PG사 정책, 전자상거래법, 고객사 운영 가이드가 우선한다.

### 제 16조의2. 환불 수단 및 정산 처리 기준

① WMS는 환불 승인 여부와 환불 수단을 분리하여 저장한다. `REFUND_APPROVE`는 환불 가능 상태를 의미하며, 실제 결제 취소 또는 정산 실행은 고객사 또는 결제 시스템의 확정 응답 이후 완료 상태로 전환한다.

② 결제수단별 기본 환불 처리 기준은 다음과 같다.

| 결제수단             | 기본 처리 기준                                    | 예외 및 보류 기준                                                                       |
| -------------------- | ------------------------------------------------- | --------------------------------------------------------------------------------------- |
| 신용카드·체크카드    | 반품 확정 후 승인 취소 또는 카드사 청구 취소 요청 | 카드사 취소 실패, 부분 취소 불가, 고객사 정산 정책 충돌 시 `CLIENT_APPROVAL_REQUIRED`   |
| 무통장·계좌이체      | 검수 완료 후 고객 명의 실명 계좌로 환불           | 계좌 정보 불일치, 예금주 불일치, 본인 확인 실패 시 `REFUND_HOLD`                        |
| 휴대폰 결제          | 당월 취소는 결제 취소 우선                        | 익월 취소, 통신사 취소 제한, 고객사 포인트 환불 정책 충돌 시 `CLIENT_APPROVAL_REQUIRED` |
| 포인트·적립금·예치금 | 주문 시 사용분을 차감·복원하고 지급 포인트는 회수 | 유효기간 만료, 프로모션 포인트, 고객사 정책 충돌 시 고객사 기준 적용                    |
| 복합 결제            | 원 결제수단별 비율에 따라 분리 환불               | 일부 수단 환불 실패 시 전체 환불을 완료 처리하지 않음                                   |

③ 연락 두절, 본인 확인 실패, 실명 계좌 미확인, 결제수단 장애가 발생하면 자동 환불을 진행하지 않고 `REFUND_HOLD`로 전환한다.

④ 환불 수단 변경은 단일 관리자 재량으로 처리할 수 없으며, 고객사 승인 또는 정산 담당자 승인을 받아야 한다.

⑤ 환불 처리 로그에는 원 결제수단, 환불 수단, 환불 예정액, 실제 환불액, 차감 금액, 배송비 부담 주체, PG 응답 코드, 처리 시각을 저장한다.

### 제 16조의3. 배송비 부담 및 귀책별 비용 처리 기준

① 배송비와 반품비 부담 주체는 고객 귀책, 판매자·고객사 귀책, 배송사 귀책, 물류센터 귀책, 귀책 불명확 상태를 구분하여 결정한다.

| 귀책 유형                   | 배송비·반품비 기본 처리             | 자동 처리 가능 여부                                |
| --------------------------- | ----------------------------------- | -------------------------------------------------- |
| 단순 변심 또는 고객 귀책    | 고객 부담 원칙                      | 고객사 정책이 명확하고 증빙 충족 시 가능           |
| 오배송·파본·표시광고 불일치 | 고객사 또는 판매자 부담 원칙        | 고객사 계약 및 증빙 확인 후 가능                   |
| 배송사 귀책 파손            | 배송사 클레임 또는 고객사 부담 검토 | 배송사 로그·외부 포장 이미지 등 증빙 2개 이상 필요 |
| 물류센터 귀책               | WMS 또는 고객사 내부 정산 기준 적용 | 물류센터 작업 로그와 출고 이미지 확인 필요         |
| 귀책 불명확                 | 고객에게 비용을 자동 부과하지 않음  | `REFUND_HOLD` 또는 `CLIENT_APPROVAL_REQUIRED`      |

② 귀책이 불명확한 상태에서 고객에게 배송비 또는 반품비를 자동 차감하지 않는다.

③ 배송비 차감이 필요한 경우 최종 판정 로그에 비용 부담 주체, 차감 금액, 근거 조항, 귀책 증빙, 승인자를 저장한다.

④ 고객사 정책이 배송비 부담 기준을 별도로 정한 경우 고객사 계약 정책을 우선한다. 단, 법령상 소비자에게 불리하게 적용될 수 있는 기준은 고객사 승인 또는 법무 검토 대상으로 이관한다.

⑤ 배송사 귀책으로 추정되더라도 상품이 위생 위험, 구성품 누락, 인증코드 사용, 불법복제본 의심 상태이면 정상 재고 또는 자동 환불 대상으로 바로 처리하지 않는다.

### 제 16조의4. 해외주문·디지털·특수 상품군 예외 기준

① 해외주문 도서, 직수입 도서, 주문 제작 또는 고객사 지정 특수 상품은 단순 변심 자동 환불 또는 자동 승인 대상에서 제외한다.

② 전자책, 디지털 콘텐츠, 다운로드 코드, 인증코드, 쿠폰, 시리얼 코드 등 복제 가능하거나 사용 여부 확인이 필요한 상품은 사용 개시 또는 코드 노출·등록 이력이 확인되면 `REJECT` 또는 `REFUND_HOLD`로 처리한다.

③ 수험서, 문제집, 워크북, 법령집, 사전, 만화, 화보집, 음반·DVD·S/W 등 단시간 열람 또는 복제가 가능한 상품군은 고객사 정책이 명확하지 않으면 `AUTO_PASS` 대상에서 제외하고 `HITL_REQUIRED`로 이관한다.

④ 해외주문·특수 상품에서 오배송, 파본, 표시·광고 불일치가 증빙으로 확인되면 단순 변심 제한 조항보다 하자·계약 불일치 특례를 우선 검토한다.

⑤ 특수 상품군 판정 로그에는 상품군 코드, 고객사 정책 ID, 사용·개봉 여부, 구성품 확인 결과, 인증코드 사용 여부, 적용 조항을 저장한다.


### 제 16조의5. 해외주문 도서 수수료 공제 및 부분 환불 기준

① 해외주문 도서에 대한 단순 변심 반품 건은 제 16조의4 ①에 따라 자동 환불·자동 승인 대상에서 제외되므로, 반드시 `HITL_REQUIRED` 또는 `CLIENT_APPROVAL_REQUIRED` 절차를 경유한 이후에만 처리를 확정한다. 해당 절차를 완료한 건에서 고객사 플랫폼 약관에 수수료 공제 부분 환불이 명시된 경우 `PARTIAL_REFUND_APPROVED` 액션을 적용하고, 전액 환불(`REFUND_APPROVE`) 대신 수수료를 차감한 차액만 환불한다.

② 수수료 공제 범위는 플랫폼별 약관을 우선 기준으로 하되, 약관이 누락되거나 불명확한 경우 아래 WMS 기본 기준을 적용한다.

| 공제 유형          | 기본 공제율 또는 금액                                        | 적용 조건                                                                                         |
| ------------------ | ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------- |
| 해외 배송·수입 수수료 | 정가의 **7% ~ 20%** (고객사 약관 기준)                     | 고객사 플랫폼 약관에 수수료 범위가 명시된 경우 약관 기준 우선 적용                                |
| 왕복 배송비        | 고객사 정책 또는 실비 기준                                   | 단순 변심 반품 시 편도 또는 왕복 배송비를 차감할 수 있다.                                         |
| WMS 기본 상한      | 정가의 **20%** 초과 금지                                     | 고객사 약관이 없거나 불명확한 경우 정가의 20%를 초과하는 수수료 공제는 `CLIENT_APPROVAL_REQUIRED`로 이관한다. |

③ 부분 환불 연산 기준은 다음과 같이 적용한다.

```
부분 환불 금액 = 실제 결제 금액 - 수수료 공제액 - 적용 배송비
수수료 공제액 = 정가 × 플랫폼 약관 공제율 (또는 WMS 기본 공제율)
```

④ `PARTIAL_REFUND_APPROVED` 처리 시 다음 정보를 반드시 판정 로그에 저장한다.

| 저장 항목          | 내용                                                         |
| ------------------ | ------------------------------------------------------------ |
| 실제 결제 금액     | 고객이 결제한 최종 금액                                      |
| 정가               | ISBN 기준 정가 또는 고객사 제공 기준가                       |
| 적용 공제율        | 플랫폼 약관 공제율 또는 WMS 기본 공제율                      |
| 공제 금액          | 연산 결과로 산출된 공제액                                    |
| 부분 환불 금액     | 최종 차액 환불 금액                                          |
| 근거 조항          | 적용된 플랫폼 약관 조항 또는 본 조(제 16조의5) 기준 명시    |
| 처리 주체          | 관리자 ID 또는 시스템 자동 처리 여부                         |
| 고객사 승인 여부   | 고객사 약관 근거 적용 시 자동 처리 가능; 약관 불명확 시 `CLIENT_APPROVAL_REQUIRED` 후 처리 |

⑤ 부분 환불 금액이 `0원 이하`로 산출되는 경우에는 `PARTIAL_REFUND_APPROVED`를 적용하지 않고 `REJECT` 또는 `CLIENT_APPROVAL_REQUIRED`로 이관한다.

⑥ 고객사 약관에 수수료 공제가 명시되지 않은 해외주문 도서 단순 변심 건은 `PARTIAL_REFUND_APPROVED` 자동 적용을 금지하고 `CLIENT_APPROVAL_REQUIRED`로 이관한다.

⑦ 파본, 오배송, 표시·광고 불일치로 확인된 해외주문 도서 반품 건은 수수료 공제 없이 전액 환불(`REFUND_APPROVE`) 또는 하자 특례 기준을 우선 적용하며, `PARTIAL_REFUND_APPROVED`는 단순 변심 건에만 적용한다.

## 제 5 장. 고객사 승인 및 고객 이의제기 처리 정책

본 장은 고객사 정책 충돌, 법적 검토 가능성, 고객 이의제기 발생 시 AI와 WMS가 자동 확정하지 않고 승인 절차로 이관하기 위한 기준이다.

### 제 17조. 고객사 승인 필요 조건

① 다음 중 하나라도 해당하면 `CLIENT_APPROVAL_REQUIRED`로 처리한다.

| 구분          | 고객사 승인 기준                                             |
| ------------- | ------------------------------------------------------------ |
| 고액 환불     | 환불 예정액 `100,000 KRW 이상`                               |
| 고가 도서     | 정가 또는 환불 예정액이 `100,000 KRW 이상`인 도서            |
| 특수 상품     | 희귀본, 절판본, 한정판으로 고객사 또는 ISBN DB에 등록된 도서 |
| 전용 구성품   | 고객사 전용 사은품 또는 구성품 포함 상품                     |
| 세트 누락     | 세트 상품 일부 구성 누락                                     |
| 정책 충돌     | 고객사 정책과 WMS 정책 충돌                                  |
| 대량 반품     | 동일 주문 기준 `10권 이상` 반품                              |
| 반복 반품     | 동일 고객 기준 최근 `30일 이내 5건 이상` 반품                |
| FDS 고액 환불 | FDS 위험 계정의 환불 예정액이 `50,000 KRW 이상`인 경우       |
| 고객 분쟁     | 고객 이의제기 발생 건                                        |
| 법적 검토     | 법적 검토 가능성이 있는 환불 거절 건                         |
| 물류센터 귀책 | 물류센터 귀책 가능성이 있는 건                               |
| 배송사 클레임 | 배송사 클레임 연계가 필요한 건                               |

② `CLIENT_APPROVAL_REQUIRED` 상태에서는 AI가 최종 환불, 최종 거절, 최종 폐기를 수행하지 않는다.

③ 고객사 승인 요청은 등록 후 `영업일 기준 2일 이내` 발송해야 한다.

④ 고객사 승인 응답이 `영업일 기준 7일` 이상 지연되면 내부 관리자에게 1차 재알림을 발송한다.

⑤ 고객사 승인 응답이 `영업일 기준 14일` 이상 지연되면 고객사 담당자와 내부 책임자에게 2차 재알림을 발송한다.

⑥ 고객사 승인 응답이 `영업일 기준 30일` 이상 지연되면 계약상 기본 처리 원칙, 장기 보류 재고 처리 기준, 고객 응대 정책 중 하나를 적용하기 위해 내부 책임자 검토를 요청한다.

⑦ 고객사 승인 결과는 승인자, 승인 시각, 승인 내용, 최종 액션과 함께 저장한다.

### 제 17조의2. Tenant별 정책 적용 기준

① 고객사별 예외 정책은 Tenant ID, 정책 문서 ID, 정책 버전, 적용 시작일, 적용 종료일을 기준으로 분리 저장한다.

② AI와 관리자는 현재 검수 건의 Tenant ID와 일치하는 고객사 정책만 참조할 수 있다. 다른 고객사의 정책은 유사 업종 또는 유사 상품이라도 현재 건의 최종 판단 근거로 사용할 수 없다.

③ WMS 기본 정책과 고객사 정책이 충돌하는 경우 다음 우선순위를 적용한다.

| 우선순위 | 정책 유형                 | 적용 기준                                                 |
| -------- | ------------------------- | --------------------------------------------------------- |
| 1        | 법령 및 강행규정          | 고객사 정책보다 우선한다.                                 |
| 2        | 고객사 계약 정책          | WMS 기본 정책보다 우선한다.                               |
| 3        | 고객사 운영 가이드        | 계약 정책을 보완하는 범위에서 적용한다.                   |
| 4        | WMS 표준 운영 정책        | 고객사 정책이 없거나 위임된 영역에 적용한다.              |
| 5        | 외부 플랫폼 리서치 데이터 | 직접 판단 근거가 아니라 정책 설계 참고 자료로만 사용한다. |

④ 고객사 정책이 누락되었거나 최신 여부가 불명확한 경우에는 액션 위험도에 따라 다음 기준을 적용한다.

| 정책 누락 영역                        | 처리 기준                                                                                     |
| ------------------------------------- | --------------------------------------------------------------------------------------------- |
| 환불 거절, 폐기, 고객 반송            | `CLIENT_APPROVAL_REQUIRED`로 이관한다.                                                        |
| 고액 환불 또는 법적 검토 가능 건      | `CLIENT_APPROVAL_REQUIRED`로 이관한다.                                                        |
| 인증코드, 쿠폰, 시리얼 코드 포함 상품 | 사용 여부 확인 전 `REFUND_HOLD` 또는 `CLIENT_APPROVAL_REQUIRED`로 이관한다.                   |
| 자동 승인                             | WMS 기본 정책의 모든 `AUTO_PASS` 조건을 충족하고 고위험 조건이 없을 때만 제한적으로 허용한다. |
| 정상 재고 편입                        | WMS 기본 위생·식별·구성품 기준을 모두 충족한 경우에만 허용한다.                               |
| 감가 재고 편입                        | 고객사 감가 판매 허용 여부가 불명확하면 `CLIENT_APPROVAL_REQUIRED`로 이관한다.                |
| 단순 촬영 품질 문제                   | 고객사 정책 누락과 무관하게 `RECAPTURE_REQUIRED` 또는 `HITL_REQUIRED`로 처리한다.             |

⑤ 정책 변경 이후 기존 판정 건에는 변경된 정책을 소급 적용하지 않는다. 단, 법령 변경 또는 고객사 계약 변경으로 소급 적용이 필요한 경우 고객사 승인 또는 상위 승인 절차를 거친다.

⑥ 모든 최종 판정 로그에는 적용된 Tenant ID, 정책 문서 ID, 정책 버전, 검색된 RAG 청크 ID, 적용 조항을 저장해야 한다.

⑦ Tenant 정책이 충돌하거나 누락되어 `CLIENT_APPROVAL_REQUIRED`로 이관된 건은 고객사 승인 완료 전까지 최종 환불, 최종 거절, 폐기, 감가 판매를 확정하지 않는다.

### 제 18조. 고객 이의제기 처리 기준

① 고객이 AI 판정 또는 관리자 판정에 이의를 제기한 경우 해당 건은 `DISPUTE_REVIEW`로 전환한다.

② `DISPUTE_REVIEW` 상태에서는 자동 환불, 자동 거절 확정, 자동 폐기, 자동 재고 편입, 자동 고객 반송을 중단한다.

③ 고객 이의제기는 접수 후 `영업일 기준 3일 이내` 1차 검토를 완료한다.

④ 이의제기 검토 시 최초 출고 검수 이미지, 반품 입고 검수 이미지, AI BBox 탐지 결과, 관리자 검수 기록, 배송 박스 손상 증빙, 고객 제출 이미지, 주문 및 반품 이력, 적용 정책 조항, Reason Code를 확인한다.

⑤ 고객 이의제기가 인정되면 기존 `REJECT` 판정을 취소하고 `PASS_OVERRIDE`, `REFUND_APPROVE`, `CLIENT_APPROVAL_REQUIRED` 중 하나로 변경할 수 있다.

⑥ 고객 이의제기가 기각되면 기존 `REJECT` 판정을 유지하고 기각 사유를 저장한다.

⑦ 동일 고객이 최근 `6개월 이내` 이의제기를 `3회 이상` 제기하고, 그중 `2회 이상` 기각된 경우 FDS 위험 신호로 기록한다.

⑧ 고객 이의제기 기각 사유는 고객에게 과도한 내부 위험 용어를 노출하지 않고, 확인된 상품 상태와 적용 정책 기준 중심으로 안내한다.

---

## 제 6 장. 재고 격리 및 재고 편입 제한 정책

본 장은 반품 또는 중고 매입 도서가 정상 재고에 잘못 편입되는 것을 방지하기 위한 물리적, 시스템적 격리 기준이다.

### 제 19조. 격리 재고 지정 기준

① 다음 사유 중 하나라도 확인되면 도서를 정상 재고와 물리적으로 분리하고, 시스템 상태를 `QUARANTINE_STOCK`으로 지정한다.

| 격리 유형           | 해당 사유                                                                         |
| ------------------- | --------------------------------------------------------------------------------- |
| 위생 및 오염 위험   | 물젖음 의심, 곰팡이 의심, 악취 의심, 음식물 또는 음료 잔여물, 끈적임, 페이지 부착 |
| 구성품 및 인증 위험 | 구성품 누락, 인증코드 사용 여부 불명확                                            |
| 정품성 및 식별 위험 | 불법 복제본 의심, ISBN 또는 바코드 판독 불가                                      |
| 분쟁 및 귀책 위험   | 고객 분쟁 진행 중, 귀책 주체 불명확, 고객사 승인 대기                             |
| FDS 위험            | FDS 위험 계정에서 반품된 도서                                                     |

② `QUARANTINE_STOCK` 상태의 도서는 자동 판매, 자동 출고, 정상 재고 편입, 감가 재고 편입, 자동 폐기, 자동 고객 반송에서 제외한다.

③ 격리 재고는 입고 후 `24시간 이내` 물리적 격리 구역으로 이동해야 한다.

④ 격리 상태가 `7일 이상` 지속되면 관리자에게 장기 체류 알림을 발송한다.

⑤ 격리 상태가 `30일 이상` 지속되면 고객사 승인 또는 내부 폐기 검토 대상으로 승격한다.

⑥ 위생 위험 격리 재고는 다른 재고와 접촉하지 않도록 별도 보관하고, 격리 구역 이동 시 작업자 ID와 이동 시각을 저장한다.

---

### 제 20조. 정상 재고 및 감가 재고 편입 제한 기준

① 다음 사유 중 하나라도 해당하면 정상 재고로 편입할 수 없다.

| 제한 유형      | 정상 재고 편입 금지 기준                                                                                        |
| -------------- | --------------------------------------------------------------------------------------------------------------- |
| 위생 위험      | 물젖음, 곰팡이, 악취, 끈적임, 음식물 또는 음료 잔여물이 `1곳 이상` 확인된 경우                                  |
| 페이지 부착    | 물젖음 또는 오염으로 페이지가 `1페이지 이상` 서로 붙어 있는 경우                                                |
| 독서 기능 훼손 | 본문 판독 방해 오염·찢김·번짐이 `1곳 이상` 확인된 경우                                                          |
| 사용 흔적      | 일반 도서의 필기·밑줄·낙서가 `1페이지 이상` 확인되거나 문제집·수험서의 풀이 흔적이 `1문항 이상` 확인된 경우     |
| 구조 파손      | 제본 벌어짐, 제본 탈착, 페이지 분리, 페이지 누락이 `1곳 이상` 확인된 경우                                       |
| 구성품 문제    | `CORE` 구성품이 `1개 이상` 누락되거나 `AUTH` 구성품 사용 여부가 불명확한 경우                                   |
| 상품 식별 문제 | ISBN 또는 바코드 판독이 불가능하거나 불법 복제본이 의심되는 경우                                                |
| 절차상 보류    | 고객 이의제기, FDS 위험 계정, 고객사 승인 대기, `REFUND_HOLD`, `DISPUTE_REVIEW`, `QUARANTINE_STOCK` 상태인 경우 |

② 정상 재고 편입은 `AUTO_PASS` 또는 관리자 `PASS` 판정이 있는 경우에만 가능하다.

③ 감가 재고 편입은 독서 기능이 유지되고 위생, 구성품, 정품성 문제가 없는 경우에만 가능하다.

④ 사용 흔적에 따른 재고 편입 단계는 다음과 같이 적용한다.

| 사용 흔적 수준                             | 처리 기준                                                       |
| ------------------------------------------ | --------------------------------------------------------------- |
| 0페이지                                    | 다른 결격 사유가 없으면 `AUTO_PASS` 또는 `NORMAL_STOCK` 후보    |
| 일반 도서 1~2페이지, 연필 또는 경미한 표시 | `NORMAL_STOCK` 금지, `DISCOUNT_STOCK` 후보 또는 `HITL_REQUIRED` |
| 일반 도서 3~5페이지                        | `CUSTOMER_FAULT` 추정 및 `REFUND_HOLD`                          |
| 일반 도서 5페이지 초과                     | `REJECT`                                                        |
| 문제집·수험서 1문항 이상                   | `REJECT`                                                        |
| 볼펜·매직·형광펜이 본문 영역 침범          | 페이지 수와 관계없이 `REJECT` 가능                              |

⑤ 감가 재고 편입은 다음 조건을 모두 충족할 때만 허용한다.

| 감가 재고 허용 조건 | 기준                                                                              |
| ------------------- | --------------------------------------------------------------------------------- |
| 훼손 면적           | 훼손 면적 비율이 `2.0% 초과 5.0% 이하`일 것                                       |
| 훼손 위치           | 바코드, ISBN, 본문, 제본부, 인증코드 등 중요 영역 손상이 없을 것                  |
| 훼손 성격           | 표지 모서리 찍힘, 표지 생활 흠집, 책배 경미한 오염처럼 독서 기능에 영향이 없을 것 |
| 위생 상태           | 물젖음, 곰팡이, 악취, 끈적임, 음식물 잔여물이 없을 것                             |
| 구성품 상태         | `CORE` 및 `AUTH` 구성품이 모두 확인될 것                                          |
| 절차 상태           | 고객 이의제기, 환불 보류, 고객사 승인 대기 상태가 아닐 것                         |

⑥ `REJECT`, `REFUND_HOLD`, `CLIENT_APPROVAL_REQUIRED`, `DISPUTE_REVIEW`, `QUARANTINE_STOCK` 상태의 도서는 정상 재고 또는 감가 재고로 편입할 수 없다.

---

### 제 21조. 폐기 및 고객 반송 기준

① 다음 사유 중 하나라도 확인되면 고객사 정책에 따라 `SCRAP` 또는 `RETURN_TO_CUSTOMER` 대상으로 분류한다.

| 처리 유형             | 대상 사유                                                                                        |
| --------------------- | ------------------------------------------------------------------------------------------------ |
| 위생상 재판매 불가    | 곰팡이 확인, 2차 검수로 확인된 심한 악취, 음식물 또는 음료 잔여물 확인, 심한 물젖음, 페이지 부착 |
| 상품성 회복 불가      | 훼손 면적 `10.0% 초과`, 본문 판독 불가, 제본 탈착, 페이지 분리                                   |
| 정품성 또는 권리 문제 | 불법 복제본 의심, 인증코드 사용 확인                                                             |
| 고객 귀책 확정        | 고객 귀책으로 확정된 핵심 구성품 누락, 고의 훼손 정황 확인                                       |

② 최종 처리 액션은 고객사 정책, 상품 상태, 분쟁 여부에 따라 `SCRAP` 또는 `RETURN_TO_CUSTOMER` 중 하나로 결정한다.

③ 분쟁 중인 도서는 고객사 승인 전까지 폐기할 수 없다.

④ 폐기 또는 고객 반송 처리 시 처리 사유, 승인자, 처리 시각, 근거 이미지, 적용 정책 조항을 저장한다.

⑤ `SCRAP` 처리 대상이라도 고객사 계약 또는 법적 분쟁 가능성이 있으면 `CLIENT_APPROVAL_REQUIRED`를 우선 적용한다.

---

## 제 7 장. 증빙 보존 및 감사 로그 정책

본 장은 AI 자동 판정, HITL 관리자 검수, FDS 판정, 고객 이의제기, 환불 보류, 거절 처리에 대한 사후 증빙을 확보하기 위한 저장 기준이다.

### 제 22조. 검수 증빙 필수 저장 기준

① WMS는 모든 AI 검수 및 HITL 검수 건에 대해 다음 증빙 데이터를 저장한다.

| 구분             | 필수 저장 항목                                                     |
| ---------------- | ------------------------------------------------------------------ |
| 주문 정보        | 주문 ID, 상품 ID, Tenant ID, 고객 ID 또는 비식별 고객 키           |
| 시각 정보        | 반품 접수 시각, 검수 시작 시각, 검수 완료 시각                     |
| 이미지 정보      | 최초 촬영 이미지, 재촬영 이미지, AI 훼손 탐지 BBox 이미지          |
| 식별 정보        | 바코드 및 ISBN OCR 결과, 주문 ISBN과 촬영 ISBN 비교 결과           |
| AI 판정 정보     | AI 검수 모듈 판정값, 정책 판정 모듈 판정값, 판정 검증 모듈 판정값  |
| 관리자 판정 정보 | 관리자 최종 판정값, 오버라이드 사유, 승인자 정보                   |
| 귀책 정보        | 고객 귀책, 배송사 귀책, 물류센터 귀책, 귀책 불명확 후보값과 확정자 |
| 정책 정보        | 적용 정책 조항, Reason Code, 최종 처리 액션                        |

② `REJECT`, `REFUND_HOLD`, `CLIENT_APPROVAL_REQUIRED`, `SCRAP`, `RETURN_TO_CUSTOMER` 처리 건은 근거 이미지 1개 이상과 Reason Code 1개 이상을 포함해야 한다.

③ 증빙 이미지가 없거나 판독 불가능한 경우 AI는 `REJECT` 또는 `AUTO_PASS`를 확정하지 않고 `HITL_REQUIRED`로 이관한다.

④ AI 판정과 관리자 판정이 다른 경우 관리자는 `OVERRIDE_REASON`을 필수 입력해야 한다.

⑤ 고객 귀책, 배송사 귀책, 물류센터 귀책 확정 건은 서로 일치하는 증빙 2개 이상을 저장해야 한다.

---

### 제 23조. 증빙 보존 기간 및 개인정보 보호

① 일반 검수 건의 증빙 이미지는 최소 `6개월간` 보관한다.

② `AUTO_PASS` 처리 건의 증빙은 최소 `6개월간` 보관한다.

③ `REJECT`, `REFUND_HOLD`, `CLIENT_APPROVAL_REQUIRED`, `DISPUTE_REVIEW` 처리 건의 증빙은 최소 `12개월간` 보관한다.

④ FDS 위험 계정 관련 증빙은 마지막 위험 이벤트 발생일로부터 최소 `18개월간` 보관한다.

⑤ 고객 이의제기, 법적 분쟁, 고객사 승인 대기 건은 분쟁 종료 또는 승인 완료 전까지 삭제할 수 없다.

⑥ 개인정보, 얼굴, 주소, 전화번호, 결제정보, 송장번호 등 도서 검수와 직접 관련 없는 민감정보가 이미지에 포함된 경우 마스킹 또는 별도 삭제 대상으로 분류한다.

⑦ 이미지 업로드 시 시스템은 개인정보 포함 가능 영역을 자동 탐지하여 마스킹을 우선 수행한다.

⑧ 자동 마스킹 실패 또는 마스킹 여부가 불명확한 이미지는 AI 개선 데이터셋 후보로 사용할 수 없다.

⑨ AI 개선 데이터셋에는 원본 이미지가 아니라 비식별화된 마스킹본만 사용할 수 있다.

⑩ 원본 증빙 이미지 접근 권한은 관리자, 감사 담당자, 고객사 승인 담당자 등 필요한 역할로 제한한다.

---

### 제 24조. 감사 로그 변경 금지 원칙

① AI 판정 로그, 관리자 판정 로그, Reason Code, 적용 조항, 최종 액션은 임의 수정할 수 없다.

② 판정값 변경이 필요한 경우 기존 로그를 수정하지 않고 별도의 정정 로그를 추가한다.

③ `REJECT`에서 `PASS`, `AUTO_PASS`, `REFUND_APPROVE`로 변경하는 경우 단일 관리자 권한으로 처리할 수 없다.

④ 정정 로그에는 정정 요청자, 정정 승인자, 정정 일시, 기존 판정값, 변경 판정값, 변경 사유, 관련 증빙, 고객사 승인 여부를 포함한다.

⑤ 고액 환불, FDS 위험 계정, 인증코드 포함 상품, 고객 이의제기 건의 정정은 2인 승인 또는 고객사 승인을 요구한다.

---

## 제 8 장. 정책 품질 점검 및 AI 개선 데이터 관리

본 장은 정책 변경, AI 오탐, AI 미탐, 관리자 오버라이드, 반복 오류를 관리하기 위한 기준이다.

### 제 25조. 정책 품질 점검 기준

① WMS 운영팀은 위험 수준에 따라 일일, 주간, 월간 점검 지표를 분리하여 관리한다.

| 점검 주기 | 점검 지표                                                                           | 재검토 기준                         | 초과 시 처리                                 |
| --------- | ----------------------------------------------------------------------------------- | ----------------------------------- | -------------------------------------------- |
| 일일      | 개인정보 마스킹 실패 건                                                             | 1건 이상                            | AI 개선 데이터셋 사용 금지 및 접근 권한 점검 |
| 일일      | `REJECT`, `REFUND_HOLD`, `DISPUTE_REVIEW`, `QUARANTINE_STOCK` 상태의 재고 편입 시도 | 1건 이상                            | 시스템 차단 및 관리자 알림                   |
| 일일      | 하드 리미트 미탐 의심 건                                                            | 1건 이상                            | 해당 유형 자동 승인 중단 및 HITL 강화        |
| 주간      | `PASS_OVERRIDE` 비율                                                                | 관리자별 `5.0% 초과` 또는 10건 이상 | 샘플 감사 또는 고위험 건 전수 감사           |
| 주간      | 장기 고객사 승인 대기 건                                                            | `14일 이상` 대기 건 발생            | 고객사 및 내부 책임자 재알림                 |
| 주간      | `REFUND_HOLD` 장기 체류 비율                                                        | `7일 이상` 체류 건이 `10.0% 초과`   | SLA 재점검 및 책임 부서 확인                 |
| 월간      | `AUTO_PASS` 후 고객 클레임 발생률                                                   | `3.0% 초과`                         | 자동 승인 기준 강화                          |
| 월간      | `REJECT` 후 고객 이의제기 인정률                                                    | `5.0% 초과`                         | 거절 기준 재검토                             |
| 월간      | `HITL_REQUIRED` 비율                                                                | 전체 검수 건의 `40.0% 초과`         | 촬영 기준 및 정책 모호성 재검토              |
| 월간      | AI 오탐률 및 AI 미탐률                                                              | 월간 증가 추세 발생                 | AI 검수 기준 및 정책 매칭 기준 재검토        |
| 월간      | FDS 위험 계정 판정 후 실제 훼손 확인률                                              | 낮을 경우                           | FDS 조건 완화 또는 식별 키 재검토            |
| 월간      | 정상 재고 편입 후 재클레임 발생률                                                   | 증가 추세 발생                      | 재고 편입 기준 강화                          |
| 월간      | Tenant 정책 충돌 건                                                                 | 1건 이상 반복                       | Tenant 정책 버전 및 RAG 청크 매핑 재검토     |

② 정책 품질 점검 결과는 다음 정책 개정 시 반영한다.

③ 동일 유형의 오탐 또는 미탐이 최근 `30일 이내 3회 이상` 반복되면 AI 개선 데이터셋 후보로 저장한다.

④ 정책 품질 점검 시 자동 판정 기준, 관리자 판정 기준, 고객사 승인 기준이 서로 충돌하는지 함께 검토한다.

⑤ 고위험 이벤트는 월간 점검을 기다리지 않고 즉시 시스템 개선 또는 자동 판정 중단 대상으로 등록한다.

### 제 26조. AI 개선 데이터셋 후보 기준

① AI가 표지 디자인을 훼손으로 오탐한 건, 물젖음 또는 곰팡이를 미탐한 건, ISBN 또는 바코드를 잘못 인식한 건, 구성품 누락을 탐지하지 못한 건, 관리자 오버라이드가 발생한 건, 고객 이의제기가 인정된 건은 AI 개선 데이터셋 후보로 저장한다.

② 동일 ISBN 또는 동일 표지 유형에서 반복 오류가 `3회 이상` 발생한 경우 AI 개선 데이터셋 후보로 우선 저장한다.

③ AI 개선 데이터셋 후보는 개인정보를 제거하거나 마스킹한 뒤 관리한다.

④ AI 개선 데이터셋으로 사용하기 전 고객사 계약 및 개인정보 처리 기준을 확인한다.

⑤ 반복 오탐 유형은 정책 판정 프롬프트, AI 검수 모듈 탐지 기준, 자동 판정 기준 중 어느 영역에서 발생했는지 분류한다.

⑥ AI 개선 데이터셋에 포함되는 이미지는 원본 증빙 이미지가 아니라 비식별화·마스킹 처리된 별도 사본으로 관리한다.
